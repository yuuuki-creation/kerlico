## 3. 组合由独立维度和约束共同决定

以 VLESS 为例，应分别表达代理协议、传输、安全、协议内 Encryption、flow、数据报编码和复用。**REALITY 不是 TCP 的子协议，Vision 也不是 REALITY 的别名。**它们能否搭配须看角色、连接类型及专用验证。其他协议可有自身 QUIC、加密或会话模型，不能机械套入同一参数集合。[M-vless] [S-vless] [X-vless] [X-stream]

### 3.1 各核心的传输与安全选择边界

| 核心/适用路径 | 传输或包装集合 | 安全/附加维度 | 关键限制 |
| --- | --- | --- | --- |
| mihomo VLESS 出站 | 默认 TCP、ws、http、h2、grpc、xhttp | TLS、REALITY、ShadowTLS/Restls/JLS；Encryption、Vision、packetaddr/XUDP | 各分支传参不同，不能统一打勾 [M-vless] |
| mihomo VLESS 入站 | 默认 TCP、WS、gRPC、XHTTP 配置 | 证书 TLS、REALITY、ShadowTLS/Restls/JLS、decryption、用户 flow | 证书与特殊模式互斥；无安全/decryption 要显式允许不安全 [M-vlessi] |
| mihomo VMess | 出站 TCP/ws/http/h2/grpc/mekya/mkcp(kcp)；入站 TCP/WS/gRPC/Mekya/mKCP | 内层 cipher；TLS/REALITY/ShadowTLS/Restls/JLS/TLSMirror 等互斥选择 | 特殊安全要求 TLS=true；mKCP 拒绝 ShadowTLS/Restls/JLS；本轮未见 VMess 专用 XHTTP 分支 [M-vmess] [M-vmessi] |
| mihomo Trojan | TCP、WS、gRPC | TLS 类安全、REALITY/ShadowTLS/Restls/JLS 互斥，可加 SS 内容包装 | 不继承 VLESS 的 XHTTP/H2/Mekya 集合 [M-trojan] |

| sing-box VMess/VLESS/Trojan | 不设置 transport 即直接 TCP；显式类型仅 http/ws/quic/grpc/httpupgrade | TLS/REALITY；VLESS flow；各协议自己的 packet/mux | raw、tcp、xhttp、splithttp 不是该版本 transport 枚举 [S-v2opt] [S-v2ray] |

| xhttp/splithttp | none、TLS、REALITY | 无安全选 H1.1；REALITY 选 H2；普通 TLS 按 ALPN 选 H1.1/H2/H3；mode/下载配置另限 [X-xhttp] |
| grpc | none、TLS、REALITY 在允许名单 | 完整握手互通仍待核 [X-stream] |
| ws/websocket、httpupgrade、kcp/mkcp | none、TLS | REALITY 被公共构建拒绝 [X-stream] |
| hysteria | 必须 TLS，version=2 | 还需协议认证/validator；业务 UDP 要专用 InterConn，不是任意流 [X-hy] [X-hyc] |
| masque | 必须 TLS | 只允许 masque 代理角色；H2/H3 按 ALPN 和监听设置 [X-reg] [X-masque] |
| xdrive | 特殊存储承载；REALITY 拒绝 | 只许 VLESS Encryption，禁止 flow，普通客户端需 Mux.Cool，反向模式有例外 [X-reg] [X-method] |

Xray 的 method 有值时覆盖 network；rawSettings/xhttpSettings 优先于旧 tcpSettings/splithttpSettings。旧独立 h2/h3/http、quic 传输和 security=xtls 明确移除；这与 XHTTP 内部选 H3 是两件事。XDRIVE 的 local/google-drive/template/s3 等服务自身也有组合限制，不作为通用传输插件承诺。[X-stream] [X-method]

### 3.2 VLESS 正向、拒绝和待核组合

以下 `V-` 编号是观察项，可由后续 kerlico 任务引用。TLS/REALITY 参数需与对端相容；表中普通 flow 表示未启用 Vision，Encryption=none 仅表示未启用 VLESS 自身加密。

| ID | 核心、方向与传输 | 安全 / flow / Encryption | 判定与数据/复用限制 | 证据 |
| --- | --- | --- | --- | --- |
| V-01 | mihomo 出 TCP | TLS 或 REALITY；普通 flow | 路径；REALITY 要 TLS=true、有效参数与可用 client fingerprint | [M-vless] [M-reality] [M-tls] |
| V-02 | mihomo 出 gRPC（H2 承载） | TLS 或 REALITY；普通 flow | 路径；不能由此外推任意对端版本互通 | [M-vless] |
| V-03 | mihomo 出 WS | REALITY；普通 flow | **未接入此分支**：WS 分支未传入 REALITY；接受全局参数不足以登记支持 | [M-vless] |
| V-04 | mihomo 入 WS | REALITY；普通 flow | 外层 REALITY listener 后接 WS handler 的路径；与 V-03 不对称，互通待验 | [M-vlessi] |
| V-05 | mihomo 出 XHTTP H1/H2 | 普通 TLS 或特殊安全；普通 flow | 流安全选择路径包含 REALITY/ShadowTLS/Restls/JLS；仍受 mode 条件限制 | [M-vless] |
| V-06 | mihomo 出 XHTTP H3，上/下载方向 | 普通 TLS；普通 flow | 路径；明确拒绝 REALITY/ShadowTLS/Restls/JLS 等特殊安全 | [M-vless] |
| V-07 | mihomo 出站所选传输 | Vision | **条件**：须识别 TLS 1.3 或 VLESS Encryption 连接；无此连接失败，不统一勾选每种传输 | [M-vision] [M-vless] |
| V-08 | mihomo 入普通 UDP command | Vision | **拒绝**；Mux/XUDP 是不同命令路径，不能概括为所有 UDP 都不可用 | [M-vudp] |
| V-09 | mihomo 出 XHTTP | stream-one + download-settings | **拒绝**；auto/stream-up/stream-one/packet-up 与上下行配置要分别验证 | [M-vless] |
| V-10 | sing-box 入/出直接 TCP（不设置 transport） | TLS；普通 flow | 路径；证书、ALPN、引擎和对端条件另验 | [S-vless] [S-vlessi] |
| V-11 | sing-box 入/出直接 TCP | REALITY；普通 flow | 条件：客户端须 TLS+uTLS，双方 `with_utls` | [S-reality] [S-realitys] |
| V-12 | sing-box 入/出直接 TLS/REALITY 流 | Vision | 条件：flow 只接受空或 xtls-rprx-vision，运行时须识别支持的 TLS/uTLS 连接 | [S-vision] [S-vless] |
| V-13 | sing-box 入/出 http/ws/grpc/httpupgrade | REALITY；普通 flow | 共享构造接受；framing/ALPN/对端及包装连接行为仍待核，不能记为全部可用 | [S-v2ray] [S-reality] |
| V-14 | sing-box 包装传输 | Vision | 构造字段存在不足以证明包装后仍满足连接识别前提；**待核实** | [S-vision] [S-vless] |
| V-15 | sing-box 入/出 QUIC transport | TLS / REALITY | TLS 路径需 with_quic；REALITY 在 QUIC TLS 转换路径失败 | [S-v2ray] [S-quicdep] |
| V-16 | sing-box 入/出 XHTTP | 任意本表安全/flow | **无该类型入口**，unknown transport type；仅限本固定版本 | [S-v2opt] [S-v2ray] |
| V-17 | sing-box 服务端直接 UDP command | Vision | **拒绝**；XUDP 是另一条命令路径，不能合并为一个 UDP 标记 | [S-vservice] |
| V-18 | Xray 入/出 RAW | TLS；flow 空 | 构建与普通 VLESS 流路径 | [X-vless] [X-stream] |
| V-19 | Xray 入/出 RAW | TLS/REALITY + Vision，Encryption=none | 条件：双方 flow 相容，运行路径检查直接安全连接，普通 TLS 要 TLS 1.3 | [X-vlessi] [X-vlesso] |
| V-20 | Xray 出 XHTTP | TLS；flow 空 | TLS 拨号路径；HTTP 版本、mode 和独立下载另限 | [X-xhttp] |
| V-21 | Xray 出 XHTTP | REALITY；flow 空 | 明确 REALITY 拨号，选 H2，不能写成 H3+REALITY | [X-xhttp] |
| V-22 | Xray 公共构建 gRPC | REALITY；flow 空 | 允许名单接受，完整握手和互通未核完 | [X-stream] |
| V-23 | Xray 公共构建 WS/HTTPUpgrade/mKCP/XDRIVE | REALITY | **拒绝** | [X-stream] |
| V-24 | Xray 入/出非直接安全流，如 XHTTP | Vision，Encryption=none | flow 可解析，但运行连接类型前提不满足时失败；不能登记为无条件支持 | [X-vlessi] [X-vlesso] |
| V-25 | Xray 非 RAW | Vision + VLESS Encryption | 有 Encryption CommonConn 分支，不能绝对说 Vision 永远只支持 RAW；具体传输仍需复核，XDRIVE 例外见 V-27 | [X-vlesso] |
| V-26 | Xray 普通客户端 XDRIVE | Encryption 非 none，flow 空 | 专用检查：需 mux enabled、并发非负，UDP443 不能 skip；反向模式另有例外 | [X-reg] [X-method] |
| V-27 | Xray XDRIVE | Vision、Encryption=none 或非 VLESS | **专用验证拒绝**，不能由 V-25 的一般分支推出可用 | [X-reg] |
| V-28 | Xray VLESS + MASQUE 传输 | 任意 | **角色验证拒绝**，该传输只给 masque 代理 | [X-reg] |
| V-29 | Xray 出站公网目标 RAW | 无外层安全，Encryption=none | 构建拒绝；受信私有目标或启用 Encryption 有独立例外 | [X-reg] |

Xray 入站 flow 为空或 xtls-rprx-vision，出站另有 -udp443 扩展并归一线上标识；入站用 decryption，用户项不能再带 encryption，出站 encryption 必须显式给出 none 或有效构造。[X-vless] mihomo 入站无安全/decryption 时需显式 allow-insecure，不能把 none 当无条件默认。[M-vlessi]

### 3.3 UDP、编码和复用不能合成一个开关

| 核心/项目 | 已核实限制 | 证据 |
| --- | --- | --- |
| mihomo sing-mux | parser 在出站构造后包裹适配器；only-tcp 为真时包仍交底层；对端须理解相应编码 | [M-reg] [M-mux] |
| mihomo VMess/VLESS | packetaddr、XUDP、普通包编码分别选择；Vision 普通 UDP command 拒绝不等于 XUDP 全不可用 | [M-vmess] [M-vless] [M-vudp] |
| sing-box VLESS/VMess | VLESS nil 默认 XUDP；显式空/packetaddr/xudp 分开；packetaddr 包路径拒绝域名目的地 | [S-vless] [S-vmess] |
| sing-box 通用 mux | h2mux/smux/yamux，padding/Brutal 等另限；不是 Xray Mux.Cool 的同义名称 | [S-mux] |
| sing-box UoT | v1/v2；SOCKS/SS/Naive 等各自接入，对端要理解该扩展；SS UoT 启用后不再构造通用 mux client | [S-socks] [S-ss] [S-naive] |
| sing-box TUIC | native/quic relay 与 udp_over_stream 扩展分开，配置存在冲突限制 | [S-tuic] |
| Xray Vision | 客户端业务 UDP 走 XUDP/Mux；默认 Vision 拒绝 UDP/443，-udp443 放行；服务端拒绝直接 UDP，允许的 mux 通道限 UDP | [X-vlessi] [X-vlesso] |
| Xray SOCKS/SS | 原生 UDP 走独立数据报拨号，不自动经过为 TCP 配置的 WS/TLS 等流传输；另加 XUDP 要单测 | [X-socks] [X-ss22] |
| Xray Mux.Cool / XUDP | TCP 并发、XUDP 并发、UDP443 策略分别构建，不能仅凭 enabled 推定对端兼容 | [X-reg] [X-mux] |
| XHTTP xmux / AnyTLS 会话复用 | 分别属于各自连接管理，不等同代理层 Mux.Cool 或 sing-mux | [X-method] [S-anytls] [M-anytls] |

同理，入口 Full-cone 映射不能证明任意出站与远端 NAT 端到端具有相同行为。协议所承载的 UDP、底层 UDP、逐包多目标与回写来源，应在测试任务中分别说明。
