## 密码与数据格式

1. 凭据为大小写敏感用户名与密码。`SHA256(password || 0x00 || username)` 为基础秘密；用户名最多 64 字节。取系统 Unix 秒按 120 秒就近舍入、以 uint64 大端编码并 SHA256 得到盐，PBKDF2-HMAC-SHA256/64 生成 32 字节密钥。初始接收尝试前一、当前、后一盐桶；已建立载体/会话保持选中的密钥，不能在中途自行刷新造成不兼容。
2. 线格式只使用 XChaCha20-Poly1305，24 字节 nonce、16 字节 tag、无额外关联数据。nonce 末 4 字节是 `SHA256(username || nonce[0..16])` 的前 4 字节，用于候选用户筛选，不能代替完整认证。
3. TCP 每方向只在首次发送 nonce，此后每次加密/解密前以**大端**方式将整个 24 字节 nonce 加一；元数据和非空负载各消耗一次操作。溢出必须关闭，失败不能继续使用不确定的计数器。
4. 每段元数据明文固定 32 字节，控制类型 2/3 为开会话请求/回应、4/5 为完整关闭请求/回应；数据/ACK 类型 6–9，低熵数据 10/11。会话 ID 32 位、零保留；数据序号和累积 `unAckSeq` 均 32 位。实际元数据校验是当前分钟前后各 1 分钟，严格于协议说明中笼统的“四分钟”，不能放宽为四分钟。
5. 逻辑会话承载精简 SOCKS5 请求/回应（`05 CMD 00 ADDR`，无额外 SOCKS 方法协商）。TCP 与 UDP Associate 分别为命令 1/3。UDP 包隧道是 `00 || u16长度 || SOCKS5 UDP包 || ff`，包内地址保留真实来源；由 `DatagramAssociation` 提供 Full Cone。UDP 目标、域名、IPv4 优先和地址族由统一出口处理。
6. TCP 应用块最大 32768 字节；低熵模式 32 最大 32764，防止 16 位编码长度溢出。四种模式分别每 8 字节容纳 4/5/6/7 原密文字节；半掩码各有 16/20/24/28 个 1，旋转由低/高半字节编码右/左移。末尾不足块的未使用选中位同属填充；必须校验统一填充极性、掩码数、旋转与长度，再验证保留的 AEAD tag。不是额外加密或安全保证。
7. 官方 Session 的关闭是完整关闭，没有独立 `CloseWrite`；接收缓冲可排空，但不能据此承诺关闭写方向后仍可等待新反向数据。kerlico 的 `tcp_eof` 必须为 false，不发明私有半关闭扩展。

## 已复现的原 UDP 密码学限制

两版本的 [UDP 发送实现](https://github.com/enfein/mieru/blob/a2208ee7a38fb41d843a13ecdde858e67ef2f485/pkg/protocol/underlay_packet.go)先用 `Encrypt` 加密元数据，再从该段取出原 nonce，用同一个 block/key 调用 `EncryptWithNonce` 加密负载；底层两次均是 `AEAD.Seal(..., nonce, plaintext, nil)`，没有分离 nonce 或子密钥。v3.39.0 同样如此。

`perf-03` 的独立 `tools/mieru_nonce_probe` 直接调用两固定版本的官方 cipher API，使用合成凭据、用户名 hint 和数据，复现上述顺序：`C_meta XOR C_body = P_meta XOR P_body`。在知道 32 字节合成元数据的条件下，仅使用元数据明文和两段密文恢复了 32 字节合成负载；TCP 的递增 nonce 控制组不满足该关系。探针没有连接网络、没有做认证伪造，也没有测试真实业务端点。原始结果保留私有，来源/二进制摘要随探针记录。

这是真实线格式问题，不以“XChaCha20-Poly1305 很强”或互通成功覆盖。改变 nonce 或派生独立 key 会破坏官方 UDP 兼容，不能擅自称为同一协议。当前授权策略已确定：

- 默认及 `nodes` 仅提供 TCP 载体，仍完整提供内部 TCP、UDP 包隧道与 Full Cone。
- 官方 UDP 载体的完整线格式、ARQ、乱序、重传和流控仍实现，但只允许显式 `unsafe_udp_compatibility=true`、IP 字面量回环端点及 `local_inbounds`；不是可用于公网的认证节点。
- 本地 UDP 模式返回空认证指纹、强制回环；准备阶段和实际运行均复核，不因存在用户名/密码字段登记可靠鉴权。TCP 带该标志或在一个条目混合两种载体均拒绝。
- 出站 UDP 同样必须显式标志和字面回环服务器；域名（包括 localhost）、非回环和 IPv4-mapped IPv6 拒绝。公网 UDP 载体列为未支持，不偷偷修线格式，也不降低其他节点的认证规则。

## Rust 原语与实现边界

固定 `chacha20poly1305 0.10.1` 的 XChaCha20-Poly1305、`pbkdf2 0.12.2`、`sha2 0.10.9` 和 `zeroize`；它们的许可均为 MIT OR Apache-2.0。它们是原语，不是 Mieru 双端实现或本协议安全审计。Tokio、bytes、serde、rand 和现有 core/config 契约用于 IO、配置及资源归属；不新增全局 QUIC/TLS patch。鉴权集合与隔离集合使用独立契约：TCP 鉴权指纹基于真实基础秘密，UDP 鉴权集合为空；两者都在 `mieru` 域隔离基础秘密，并在 `mieru-user` 域隔离用户名身份。同名不同密码是身份规则拒绝，不应描述为秘密相同。

服务器只在完整解密、元数据/负载/方向/非零 ID/时间校验之后建立逻辑会话，TCP 首 nonce 使用有界节点内重放表。物理载体与附加逻辑会话分别受全局和节点预算约束；身份、连接池、密钥、重放与取消域按出站实例/节点隔离。单逻辑取消不能破坏其他流的 TCP nonce 顺序。帧头/正文读取状态不能因其他事件重新开始；未完成帧时关闭载体，不重试部分加密写。

TCP/UDP 都做真实会话复用，不以逐目标单连接冒充。UDP 本地模式使用序号、累积 ACK、有限接收窗口、乱序缓冲、重复抑制、RTO/快速重传、重试上限和空闲回收；发送拥塞窗口采用有界加性增大/乘性减小，不冒充上游 CUBIC/BBR 或给出性能结论。地址/身份固定，不做 UDP 跨来源迁移、节点失败后的凭据/地址回退或端口漫游。

## 完整首轮交付与验收矩阵

本轮一次写齐：原生 Rust 双端、默认 TCP 与严格限定本地 UDP 两种载体、精简 SOCKS TCP/UDP Associate、真实复用/禁用复用、等待/首次写入握手、多用户独立节点、Full Cone 多目标包隧道、四低熵模式及合法左右旋转、随机前后填充、重放/时间/长度/资源/取消/完整关闭、UDP ARQ 与异常路径；同时写接口、Rust 测试和独立对端工具，再统一构建与集中修复。

计划基线：两载体 × 两节点地址族 × 两角色 × 复用开关 × 两握手模式，共 32 配置；低熵四模式 × 代表性的无/右/左旋转 × 两载体 × 两角色，共 48 配置。另以独立 Go 固定字节覆盖掩码、填充极性、旋转和边界长度，不以同一 Rust 编解码自端代替证明。安全 TCP 与本地不安全 UDP 结果分别列出。

回归包括 Full Cone 跨目标/跨地址族同端口和未先联系来源、独立身份链、并发/顺序复用、0/17/1200/12000/65507 字节与溢出拒绝、低熵 32764/32768 边界、UDP 丢包/重复/乱序/零窗口/重传上限、帧截断、错误秘密/hint/时间、TCP 重放、错误角色/ID、取消与预算归还、端口复用、未实现字段和公网/域名 UDP 的配置拒绝。真实对端拟用已核验固定 Mihomo 与固定官方 API 测试程序；原始版本与来源分别保存。

不提供 v2 旧协议、任意 WS/TLS/QUIC 载体、独立半关闭、端口范围/漫游、任意不受约束的 nonce 固定模式、公开 UDP 载体、管理 API、热重载、TUN、指纹或性能承诺。未知配置明确拒绝；限定构建和互通结果已单列，不从计划外推其他场景。

## 接收压力集中修正

独立 API 首轮在本地 UDP 低熵32回包出现两个时序失败。只采样自有子进程 socket，内核接收丢包达29/20，默认接收上限212992；通告窗口与内核 skb 余量不匹配。模块改为仅在自己持有的 socket 请求2 MiB SO_RCVBUF、通告接收窗口最多32，保留乱序128/待发512容量；不改全局sysctl、不缩负载或更改旧 nonce 规则。定点完整回包且drops=0后，三套88配置矩阵均通过。原失败/采样/复验保留，不能把本地兼容通过改写成公网UDP支持。
