# 为什么仓库是这个形状

操作步骤和当前决定在 `docs/reference/crates.md` 和 `docs/reference/server.md`。这篇只解释取舍。

## 两端不能共用一个带角色 feature 的协议包

Cargo 在同一次解析里合并同一个包的 features。客户端和服务端如果都依赖同一个协议包，一端打开的 `client` feature 会在另一次同时包含两端的构建里对这个包生效。没被选中的角色仍然会被编译。

所以每一端的协议代码是各自的 crate。叶子用可选依赖点名自己要的那一端。共享的帧放在没有角色 feature 的 `protocols/<id>/shared`。`kerlico-shared` 也不依赖任何角色 crate。

代价是增加协议要同时动目录和叶子的一行依赖。`kerlico-manifest` 在两边不一致时让构建失败。用程序现写一份 `Cargo.toml` 可以把名单收成目录一处，但那会变成第二套构建系统。现有的 Cargo 命令已经能把两端切开，所以没有采用那套驱动。

同名 feature 还有一个边界。两个叶子都有名为 `wireguard` 的 feature 时，一条命令同时构建两个包会把两边都打开。不对称的协议集合因此是两条命令。

## 入站不拨号

服务端要同时挂多个节点。节点的协议可以相同，也可以不同。每个节点只听 IPv4 或只听 IPv6。如果协议 crate 自己拨号，每个节点就会长出自己的出站，五种出口会在每个协议里各写一遍。

协议 crate 只把认证后的流交成 `Handoff`。`crates/outbound` 是进程里唯一会拨号的模块。节点可以在创建时指定一种出口，也可以留空。留空的判断也在这个模块里，不在节点里。

分流也挂在节点上，而不是挂成一份全局路由。匹配的是 Xray 已经在用的域名规则和 IP 分类，包括 `geosite.dat`、`geoip.dat`，以及带 `domain:`、`full:`、`keyword:`、`regexp:`、`geoip:` 前缀的文本。规则集在进程里只加载一次。节点只决定这份名单命中后用哪一个 `OutboundChoice`。Xray 的规则最后要落到某个 `outboundTag`，所以每多一种走法就要多一个出站对象。这里的五种出口和缺原生地址时的 WARP 切换仍然只有一套。节点之间不共享规则，是因为每个节点的监听和默认出口本来就可以不同。一份全局表再用入口标签过滤，会把这个差别再写一遍。

端口、来源和用户不再做一层匹配。节点已经是入口，五种出口已经是全部走法。再加上这些条件，会变成第二份路由表。

私网和本机地址在用户规则之后有一条内置的原生出口。留空时缺原生地址会改走 WARP。没有这条内置规则，局域网和发给本机的流量会在机器没有公网地址时进入 WARP。用户规则仍然可以先命中，把这些地址指到别的出口。

DNS、嗅探和 FakeDNS 放在服务端，是因为地址族和域名规则要同一份结果。协议 crate 各自解析，家族选择就会有两套。嗅探只给规则补主机名，拨号仍用报文原来的 IP。代理协议已经带了主机名，再嗅探一次会把目标改掉。FakeDNS 的假地址在规则之前还原，否则 `198.18.0.0/15` 会先被私网规则截住。

落地会让服务端叶子依赖一个客户端协议 crate。把整条流交给远端代理，用的就是该协议的客户端。这个依赖的键带 `landing-` 前缀，而且只在启用落地协议的那次构建里出现。只编入站协议的命令因此仍然不含另一端。

选定出口后只拨一次。Xray 在没有 balancer 时也是拨失败就结束连接。再自动换一个出口，计数和规则就对不上这次选择。

## WARP 是服务端的默认出站，不是可选协议

留空时优先用本机原生地址，并且优先 v4。目标只有 IPv6 时改用 v6。本机缺掉这一族时，用同一族的 WARP 补上。远端落地只在明确指定时使用，避免缺一条地址就把用户的流量交给另一台机器。

WARP 是一条用户态 WireGuard 隧道。它如果接管机器的默认路由，入站监听会被吸进自己的隧道。所以它只承载出站模块发出的流。

这条隧道和用户连接用的 WireGuard 协议必须是同一份 Rust 实现。放在协议目录里，则服务端在没编 WireGuard 入站时就没有 WARP。放在 `crates/outbound` 里，则客户端协议和出站会各写一遍。因此引擎单独占 `crates/wg`。服务端因为总是依赖出站模块，所以总是带上它。只编客户端、且不选 WireGuard 协议时不带上它。
