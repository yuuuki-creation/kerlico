# 核心类型、接口与依赖契约

状态：目标架构契约，更新日期2026-11-02。共享出站及节点责任按[0009](decisions/0009-global-egress-dispatcher.md)、[0010](decisions/0010-node-egress-modes-and-warp.md)，多用户及统计按[0011](decisions/0011-users-statistics-and-access-records.md)同步。实际Rust接口见[核心接口](interfaces/core.md)。完整元数据、配置代次及新边界不代表已实现。布局见[总体结构](architecture.md)，逐包行为见[数据路径](data-paths.md)。

## 装配与转发分开

配置、工厂注册、依赖校验和资源准备属于装配路径。连接建立后使用已经解析好的服务句柄、路由快照和实例引用，转发循环不反复查找协议名称或解析配置。

`core-api` 提供小范围的跨 package 契约，具体实现留在相应模块。第三方 runtime、协议连接类型、平台句柄和私有缓存不直接暴露给所有调用方。对通用 I/O 与取消能力选择的基础依赖可以进入契约，但不以“运行时中立”为理由自己重做一套异步执行系统。

## 标识、类型与实例

| 概念 | 含义与约束 |
| --- | --- |
| `ModuleKey` | 模块类别与稳定类型名称的组合；注册工厂时唯一，不把某个协议实例的名字放在这里 |
| `InstanceKey` | 类别与实例标签的组合；同类实例标签唯一，一个协议可有多个实例 |
| `NodeId` / 认证身份引用 | 服务端接入节点及已认证主体的独立标识；IPv4/IPv6 节点分别建立，不把明文凭据放进会话元数据 |
| 管理`UserId` / 节点成员关系 | 管理域内稳定用户标识，与可改用户名及协议凭据分开；成员关系绑定节点认证域，不自动允许跨节点凭据复用 |
| Engine运行标识 / 计量水位 | 区分重启前后的会话与批次，累计水位用于持久化去重；不能用显示用户名作为账本主键 |
| `ConfigGeneration` | 一次成功发布的配置代次；候选更新不改变当前代次，迟到的结果不能覆盖新代次 |
| `SessionId` | 一次被接纳的逻辑会话；TCP 连接与 UDP 关联分别建模，不从地址直接推导唯一性 |
| `AssociationId` / `FlowId` | UDP 的关联与关联内目标流；同时包含实例隔离信息，避免不同用户或入站串会话 |
| `ResourceId` / resource lease | 设备、监听器、连接池等运行资源及其使用凭据；资源可被多个逻辑实例引用，但实际所有者唯一 |

运行会话与资源键必须带Engine归属，管理用户及节点稳定标识按管理域保存，不能因重启重新命名而丢失历史。多Engine共存时不能使用无实例归属的进程级会话表。客户端和服务端共用核心，接入节点、已认证用户、所选出站及会话归属分开。本地路径按节点模式处理，双栈默认IPv4优先；远端保留原目标，策略归远端。设备WARP是设备级共享资源，不等于跨Engine共享会话表；见[节点设计](node-egress.md)、[0010](decisions/0010-node-egress-modes-and-warp.md)与[统计设计](statistics-and-users.md)。模块版本、内部契约版本和用户配置格式版本分别记录，不把crate版本当成稳定动态插件ABI。

## 目标信息按阶段保留

会话需要区分下列信息，不能用一个可变的 destination 字段反复覆盖：

| 信息 | 产生者 | 后续使用 |
| --- | --- | --- |
| 原始入口信息 | 入站适配器 | 接入类型、实例、来源、原始目标与已认证身份；保存入口实际看到的内容 |
| 映射恢复结果 | Fake-IP/透明接入适配 | 恢复的域名、映射凭据和入口命名空间；不能抹掉原始 IP |
| 观察结果 | 有限嗅探阶段 | 检测到的协议、域名及其来源；嗅探域名不自动成为拨号目标 |
| 路由依据 | engine 与 routing | 匹配使用的域名/IP、规则版本与待解析请求；纯匹配不修改系统网络 |
| `RouteDecision` | 路由和策略选择 | 本地/远端责任分支、固定具体出站、本地节点模式及地址候选边界；远端原目标不被改写 |
| 实际拨号结果 | net 与出站 | 远端地址、底层连接和生效选项；用于诊断与回写，不反向改变原始身份 |

建议阶段之间传递受约束的输入和结果，初始信息保持只读。不要把一个公共可变上下文交给所有并发任务任意修改；协议私有状态也不进入核心共享元数据。

地址模型区分域名和 IP，并显式携带端口、地址族及必要的 IPv6 scope 信息。模块接收经过统一校验的地址，原始字符串仅用于受控诊断；域名规范化、IDNA 和区域地址处理的具体规则留待接口设计。Fake-IP 的恢复与是否允许域名覆盖是两个独立动作。

## 跨模块契约清单

| 契约 | 提供方 / 使用方 | 输入与结果 | 责任边界 |
| --- | --- | --- | --- |
| 模块描述与工厂 | 各模块 / registry、config | 能力、选项视图、已校验构造计划 | 具体协议自己解码配置，不要求公共层认识协议结构 |
| `SessionSubmitter` | engine / 入站 | 入站上下文与流或数据报接入 | 固定会话归属并调用目标访问服务；不能通过它操作整个 engine |
| `AccessService` | egress / engine及接入适配 | 原始目标、可信节点归属、流/包模型和预算，返回通道或阶段错误 | 所有入口进入同一个Dispatcher；本地应用节点模式，远端保留原目标，不暴露凭据 |
| 出站建立 | 协议或 builtin / egress | 决策与服务句柄，返回就绪通道或阶段错误 | 核心不依赖具体协议连接类型；协议负责自己的握手 |
| `Router` | routing / egress | 目标观察和已有解析结果，返回决策或需要的额外信息 | 不直接拨号；追加解析后允许重入，但必须推进状态并限制轮数 |
| `Resolver` | dns / egress、net | 查询目的、代次、路由上下文与预算，返回解析结果 | 不用无上下文的全局解析器；引导查询不继承会造成递归的业务策略 |
| `Connector` | net / 协议、DNS | 明确的底层目标、路径约束与剩余预算，返回 I/O 通道 | 业务路由选择已经完成；保护、绑定和引导解析通过窄服务完成 |
| 平台服务 | platform 或宿主 / net、tun | 设备访问、socket 保护和受控网络操作 | 调用者拿到的是约定的能力和所有权，不是任意执行系统命令的入口 |
| 控制与观测 | engine / control | 只读状态、更新请求、操作结果 | 不暴露协议内部可变对象，控制层不绕过校验路径直接改实例 |
| 用户归属 | 节点鉴权 / 共享访问与统计服务 | 可信节点、管理用户、逻辑会话及凭据版本引用 | 不接受网络输入自报用户，不传递明文密码或认证UUID，不放宽跨节点秘密隔离 |
| 计量与记录 | 共享统计服务 / I/O适配、control | 唯一业务增量、阶段事件、时间桶、保存水位及只读查询 | 流量、速率、载体/设备开销分开，重置查询不删除历史；具体签名未实现 |

模块类别覆盖代理入/出站、解析器、策略等不同角色。同一协议可以提供多个角色描述，但只能声明自己实现的方向和 I/O 能力。传输、安全、DNS 与原始 IP endpoint 的构造接口按实际语义分别维护，不强制继承一个包办所有功能的接口。

当前源码已存在AccessService和Egress，但Egress仍按节点装配且对代理网站域名执行本地解析。唯一共享调度器、节点模式、设备WARP和远端透传尚未迁移；不要把完整目标请求上下文当作当前签名。双端一体也不表示每个协议已有双向能力。

目标所有权为一个Dispatcher唯一持有命名出站表；节点访问句柄只绑定可信来源和共享服务引用。不同代理的池、票据与必要来源作用域分别管理，不能按节点嵌套完整Outbound恢复旧结构。设备WARP由设备所有者共享管理，不属于单个节点的私有资源。

### 配置解码避免反向依赖

建议 config 输出与文件格式分开的选项视图及字段位置，由选中的工厂解码为协议私有配置，返回持有该配置的“不透明构造计划”。计划可以报告依赖、能力与资源需求，再通过工厂契约构造实例。

config不对协议私有结构做类型向下转换，也不维护包含全部协议的大枚举。当前JSON v1已有具体值表示，不透明计划仍是目标建议；本轮不另造序列化框架。未知模块只报告当前构建未注册该类型及现有能力；若app另有已知feature清单，才能进一步提示构建开关。

### 能力是组合约束

| 能力信息 | 必须表达的区别 |
| --- | --- |
| 角色 | 入站、出站、解析、选择等角色分别声明 |
| 数据模型 | 字节流、数据报、原始 IP 包不能互相冒充 |
| 数据报目标 | 固定单目标、逐包多目标，以及回包来源表达能力 |
| 传输行为 | 半关闭、目标表示、早期数据、复用及连接共享的限制 |
| 资源和平台 | 平台能力需求、独占资源、是否支持复用既有句柄 |
| 更新方式 | 新实例替换、已有会话排空、仅重启可变更；不能只写一个“支持热更新”布尔值 |

支持数据报语义不表示底层一定使用 UDP；复用与逐包多目标也不是同一项能力。不得从一个协议“支持 UDP”推导所有映射、回包或 NAT 行为均相同。

## 所有权与 Rust 表达边界

配置与路由快照在发布后只读；会话独占自己的阶段状态和流读写端。UDP 队列交接包时同时交接缓冲区所有权或明确的共享租约，不能把池中已经归还的存储继续借给异步任务。设备句柄、连接池与映射由独立资源所有者管理，使用者通过 lease 保活。

公共异步调用需要说明可取消点、截止时间和取消后仍可能发生的副作用。选用运行时后再确定 Future 的表达、线程间移动约束与动态分发形式。需要 trait 对象的接口必须满足 dyn compatibility；不能假设直接声明异步 trait 方法就能用于这种分发。依据：[Rust dyn compatibility](https://doc.rust-lang.org/reference/items/traits.html#dyn-compatibility)。

建议将必要的动态分发放在模块、会话和服务边界；编解码内部可保留具体类型。是否需要数据报批处理、缓冲池或进一步减少分配，以测量决定，不预先承诺零拷贝。

## 错误与可观测性

建议公共错误记录类别、阶段、模块/实例、会话与配置代次，并保留受控原因链。分类至少涵盖配置、能力不匹配、策略拒绝、解析、连接、协议、超时、取消、资源限制和平台失败。可重试性由失败阶段、已发送数据和操作类型决定，不能只凭一个网络错误类别判断。

连接建立前的选择失败、部分握手失败和已转发业务数据后的失败分别处理。本地只在节点模式允许的地址候选内受限尝试；远端分流失败按协议返回或结束会话，不换族、换代理、直连或WARP替代。观测若用于未来初始选择，不搬迁当前连接或UDP关联；已交付数据不重放。

计数与跟踪区分入站/出站、阶段、错误原因和代次。高频指标标签使用有界类别，域名和会话 ID 留给按需诊断，防止指标集合无限增长。密钥、口令和认证报文不进入日志；control 读取的是经过整理的状态视图。

按[0011](decisions/0011-users-statistics-and-access-records.md)，用户、节点与实际命名出站的业务量由同一计量增量归集，不把各视图或代理两条网络腿相加。带宽以有效时间窗口计算，峰值标明采样口径；在线引用与旧累计事件分开。访问、DNS、错误记录及持久用量的字段和故障边界统一见[统计设计](statistics-and-users.md)，当前Stats四类事件不等于这些接口已具备。

| `core-api/src/module.rs`、`capability.rs` | 描述、工厂、不透明构造计划和能力约束 |
| `core-api/src/services.rs`、`lifecycle.rs`、`error.rs` | 窄服务、关闭/预算契约与公共错误 |
| `core-api/src/access.rs`、`egress/src/` | 目标访问契约及独立实现，协调路由、DNS、候选安排与出口建立 |
| `engine/src/registry.rs`、`builder.rs` | 显式工厂注册、装配与资源依赖排序 |
| `engine/src/dispatch/` | 接纳会话、固定可信上下文与配置归属，调用共享访问服务；不另持出站调度表 |
| `engine/src/relay/`、`session/` | TCP/UDP 转发、关联表、包队列和会话回收 |
| `engine/src/generation.rs`、`lifecycle.rs`、`supervisor.rs` | 配置代次、资源使用期和任务所有权 |
| `config/src/document.rs`、`validate.rs`、`plan.rs` | 外层文档、通用校验、构造计划与更新差异 |
| `net/src/connector.rs`、`transport/`、`security/` | 底层连接、可复用传输和安全实现 |
| `routing/src/matcher.rs`、`ruleset.rs` | 匹配与规则快照，不承担网络 I/O |
| `dns/src/resolver.rs`、`cache.rs`、`fake_ip.rs` | 查询、分区缓存和映射租约 |
| `tun/src/adapter.rs`、`stack/` | IP 与核心数据模型的适配 |

入站数据通道、模块构造依赖、资源共享与控制接口应分别追踪，不能将所有协作关系都塞进一个可遍历的全局服务容器。[运行与配置生命周期](runtime-lifecycle.md)进一步规定这些对象何时可用和何时释放。
