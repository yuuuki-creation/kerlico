## 私有资料存放

用户明确允许将这三台机器的必要凭证复制到本项目本地，存放在被 Git 排除的 `.private/machines/`：

| 本地文件 | 用途 |
| --- | --- |
| `ssh_key` | 仅用于已授权机器访问的密钥副本 |
| `ssh_config` | 三个中性别名的 SSH 连接设置 |
| `known_hosts` | 从已有可信记录提取的主机身份资料，不能当作可忽略的检查 |
| `inventory.json` | 实际访问地址、来源对应、资源记录与验证状态 |
| `README.md` | 本地使用说明 |

以上文件不是仓库提交内容，也不作为公共文档附件。私有目录为 `0700`、文件为 `0600`；根 `.gitignore` 排除整个 `.private/`，匿名钩子额外拒绝该目录进入提交和推送历史。

本地使用入口为`ssh -F .private/machines/ssh_config perf-01`，其他两台使用对应别名。历史任务依据当时授权完成首次信任（TOFU）并保存记录，随后保持严格主机身份检查；该首次固定未经独立第三方指纹认证。三台曾登录进行只读探测和项目任务，真实记录仅在私有目录保存；本轮未重新连接。

不把这些资料上传 Git、GitHub 或其他外部凭证存储，不放入 workflow、容器镜像、构建产物或日志。其他项目和其他机器的密钥、服务令牌不随本次授权复制。

## 后续任务使用方式

框架和协议已有多批快照，当前先保留停止状态；后续按明确任务范围及[协议开发流程](protocol-roadmap.md)推进。编译测试实际开始时，保存所用提交、工具链/目标、对端版本、任务命令、环境与结果；公开记录脱敏，实际连接细节留在私有资料中。

建议把常规构建、互通测试和性能采样分开运行。互通可由两台 worker 承担不同角色，机器间通信遵循管理仓库的 Mesh 约定；同机测试可使用回环或隔离网络。跨地域网络结果单独记录，不能将链路差异归因于协议实现性能。

每项任务先明确完整交付角色和组合，集中完成首轮编码后再统一验证、修改及复验，不能用最小组合先写先测替代该流程。各组合分别记录，无效配置、错误认证、异常报文、超时、取消、关闭与资源回收均需覆盖。

[0010](decisions/0010-node-egress-modes-and-warp.md)中的设备共享WARP属于部署资源设计，不因构建测试凭据存在而获得设备配置授权。配置纯校验不得安装WARP或修改系统网络；本轮只更新文档，没有重新运行worker任务。

项目临时工作放在管理约定允许的项目工作区，构建产物及时保存到合适位置；worker 视为可重建资源，不存唯一数据。不清理他人作业和业务数据，不停用或更改 Runner、Docker、Mesh、监控、SSH 等基础服务。

早期任务曾在规定项目工作区使用已有宿主工具链及一次性Rust 1.88容器，没有更改宿主默认工具链、增加CI或注册Runner。后续仍按实际任务授权使用资源，持有凭证不等于任意运维授权。
