# Shadowsocks 2022 实际接口

状态：本轮实现已通过 worker 包级检查及固定对端限定互通。对应 P-04、K-S2；角色、组合和对端限制见测试记录。

`kerlico-ss2022` 在同一可执行程序中注册 `Ss2022Factory` 与 `Ss2022NodeFactory`，类型名均为 `ss2022`。TCP 使用固定 `shadowsocks =1.25.0` 的流原语，UDP 使用其原生加解密原语；不运行外部代理进程。所有业务目标经 `AccessService`，载体地址解析不等于业务目标解析。

## 出站选项

```json
{"server":"127.0.0.1","port":8388,"method":"2022-blake3-aes-128-gcm","key":"<标准 Base64 key>","identity_keys":[]}
```

`method` 仅接受 `2022-blake3-aes-128-gcm`、`2022-blake3-aes-256-gcm`、`2022-blake3-chacha20-poly1305`。前者 key 解码为 16 字节，后两者为 32 字节。拒绝口令和冒号拼接 key；AES 的 `identity_keys` 显式表达按路径顺序排列的至多八层身份 key，最终用户 key 放在 `key`。链内 key 必须独立。ChaCha 拒绝非空 identity 链。

出站提供 TCP（`tcp_eof=true`）与固定目标 UDP；UDP 请求/回包保持包边界，允许空负载，单包业务负载上限 65000 字节，完整 wire 上限 65507 字节。客户端按 server session 分别验证 client session 关联和 2048 包回放窗口，支持服务端 session 变更。超过 64 个活跃 server session 时丢弃新 session，60 秒无有效回包后释放对应窗口。

## 节点选项

```json
{"method":"2022-blake3-aes-128-gcm","key":"<本节点服务 key>","users":[]}
```

`users` 为空表示单用户，客户端直接使用本节点 key。AES 配置非空 `users` 时表示终端 EIH 多用户节点：`key` 为服务身份 key，用户 key 数组上限 1024；客户端使用相应用户 key 与包含服务 key 的 identity 链。拒绝重复 key、服务 key 与用户 key 相同、ChaCha 多用户。字段只接受列出的内容，relay 目标、SIP003、UoT、mux 等未知字段均拒绝。

每个节点具有独立 Context、TCP salt 回放集、用户表与 UDP 会话。`credential_fingerprints` 覆盖服务 key 和全部用户 key，供配置层拒绝 IPv4/IPv6 节点凭据重复。AEAD 提供传输保护，因此 `requires_loopback=false`；实际是否允许公网监听仍由装配/策略决定。

`supports_tcp=true`、`supports_udp=true`。engine 注入同节点 TCP/UDP socket 与 v6only 监听边界；`handle` 处理一条 TCP 流，`handle_udp` 处理整个 UDP socket。协议不重新绑定业务端口。UDP 按认证用户与 client session ID 路由，只有通过认证和回放窗口的包更新源地址，允许有效会话迁移源端口。同一 client session 可以请求多个目标，各目标均经统一服务建立固定目标数据报通道。

UDP 会话与目标关联分别持有 `StreamBudget`，因此首个目标需要两个预算名额。会话总数及每会话目标数也受 `max_streams` 限制，目标队列为 32 包，过载时丢弃完整包。会话保留时间为 `max(idle_timeout, 60 秒)`，防止提前遗忘回放状态。目标关闭后不重放先前数据；后续通过回放窗口的新数据报可重新建立该目标关联，会话及回放状态继续保留。节点取消时丢弃全部任务、通道和预算。节点观察器统计会话接受/完成、目标失败和预算丢弃。

## 交付边界

本轮提供三算法的单用户双端 TCP/原生 UDP，以及 AES 终端 EIH 多用户与客户端身份链编码。客户端链编码不代表本模块实现 relay 节点；服务端只终止本节点已配置用户，不剥离头后转发到下一 SS2022 服务器。插件、UoT、mux、relay 服务端和旧版 Shadowsocks 不在当前接口范围。

固定 Xray v26.10.29 的 8192 字节 UDP 业务包未通过，本轮该对端只按 4096 字节负载验收；本包自互通已覆盖 64000 字节。正式 CLI 的双角色、IPv4/IPv6 节点与目标、凭据隔离、TCP/UDP 同端口、v6only、域名 IPv4 优先和预算退出已完成 17 组集成检查；该轮根路径选用 AES-128-GCM 单用户，其他算法及 EIH 的线上组合依据仍分别见包级和固定对端记录。

依赖和线格式依据见[实现研究](../../reference/research_notes/ss2022-implementation.md)，真实结果见[测试记录](../testing/ss2022.md)。
