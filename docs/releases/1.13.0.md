# 1.13.0 发行说明

M11 真实化版本。对能力总表中标为已实现的 2,080 项逐项对照代码审计：1,438 项与标注一致，262 项夸大，335 项是空壳，45 项没有代码。本版本修复其中影响最大的空壳与安全问题，并把能力总表改为审计后的真实状态。逐项结果见 [M11 审计](../testing/m11-audit/README.md)。

## 安全修复

- **OpenVPN 服务端入站默认账号**：`v1.10.0` 至 `v1.12.0` 中，未配置用户的 OpenVPN 服务端入站会自动加入代码内置的固定账号口令，任何人可用这组公开凭据登录；客户端证书也不校验。现在没有成员凭据的节点拒绝启动，口令按常数时间比较，客户端证书按 `ca`、CRL、指纹、`verify-x509-name` 与 EKU/KU 校验。运行过无用户 OpenVPN 节点的部署应升级并检查连接记录。
- **路由条件 `in_type`、`in_port`、`dscp`、`uid`**：此前能解析但不参与匹配，带这些条件的规则匹配全部流量（例如 `UID,1000,REJECT` 拒绝所有连接）。现在含这些条件的规则在编译时报错。
- **Shadowsocks SIP003 插件**：未实现的插件（kcptun、restls、jls、shadow-tls 等）和未实现的参数此前静默改为明文 TCP。现在编译期报错；v2ray-plugin WebSocket 改为真实 WebSocket 帧，obfs http 修正半包读取。

## 空壳改为真实实现

- **测速与健康检查**：延迟接口此前记录常量 12/15 ms，且没有后台健康检查。现在经所选出站发 HTTP `HEAD` 实测，支持 `expected-status`、`timeout`、`lazy`，按 `interval` 后台探测；失败节点标为不可用，url-test、fallback、least-ping 按实测选择。
- **配置热重载**：`SIGHUP`、`PUT /configs`、`POST /restart` 此前只校验配置。现在串行执行重载：新配置无效时保留旧引擎；有效时排空旧引擎并启动新引擎，启动失败则恢复上一份配置。旧监听关闭到新监听绑定之间新连接被拒绝。`PATCH /configs` 仍未实现。
- **远程资源下载**：http 订阅、远程规则集、规则提供者与 Geo 文件此前只读本地文件。现在经所选出站（`proxy`/`download_detour`）下载，支持 ETag 与 Last-Modified、大小上限、原子写入缓存，失败时沿用旧缓存；规则集在运行中替换，订阅成员变化时重建引擎（已有连接被排空）。被规则引用但没有任何内容的规则集启动时报错。Geo 文件下载后运行时仍使用内置表。
- **连接表与控制接口**：`/connections` 此前恒为空。现在列出全部 TCP 流与 UDP 关联，含规则、链路、进程与实时字节数；`DELETE /connections[/{id}]` 真正断开；`interrupt-exist-connections` 生效。`/rules`、`/memory`、`/dns/query` 改用运行时真实数据。
- **OpenVPN 服务端入站**：地址池与按配置生成的 `PUSH_REPLY`、`max-clients`、`duplicate-cn`、NCP 协商、ping 与换钥、重放窗口、TLS 版本与套件、tls-crypt-v2 服务端均已实现；官方 OpenVPN 2.6.20 与 2.4.12 客户端 10 个互通用例通过。`static_key` 模式改为配置期拒绝。
- **OpenVPN 出站 tls-crypt-v2**：WKc 长度字段此前从错误位置读取，真实客户端密钥无法使用，已改正。
- **Mihomo YAML、订阅与分享链接**：此前只改名 `name`/`type`，其余字段原样透传，真实 Mihomo 配置中的多数节点无法加载。现在按类型把 Mihomo 字段映射为 kerlico 选项，三个入口共用同一映射；不支持的字段报错并指出节点与字段。
- **密钥生成**：`generate mldsa65`、`mlkem768`、`vlessenc` 此前输出 SHA-256 填充。现在输出真实 ML-KEM-768 与 ML-DSA-65 密钥；`--months` 设置证书有效期。
- **`cache.db`**：选中节点与 Fake-IP 持久化此前写同一文件并互相覆盖。现在由单一持有者分区写入。

## 行为变化

- OpenVPN 服务端 TLS 模式必须提供证书与私钥，不再自动生成自签证书；默认 `mtu` 由 1400 改为 1500；未配置保活时按 `keepalive 10 60` 运行。
- `x25519` 与 `mlkem768` 的 Hash32 改为 BLAKE3，与 Xray 一致性未对照 Xray 源码核实。
- 旧格式 `cache.db` 顶层的 Fake-IP 记录不再读取，首次启动后重新分配。
- 提交钩子的匿名检查改为批量读取对象，单次检查由约 85 秒降为约 2 秒。

## 能力总表

按审计回写：夸大项降为部分实现，空壳与缺失项降为未实现；只有指向具名测试的项记为实测通过。本版本修复的单元已按当前代码复核回填。未修复的单元（DNS 管线、`.srs`/`.mrs` 与 Geo 运行时加载、ACME、服务端 ECH、sing-mux 线格式、拨号选项覆盖、TUN 自动化等）列在 [M11 审计](../testing/m11-audit/README.md)，按后续版本推进。

## English

M11 accuracy release. All 2,080 capability-matrix items marked implemented were audited against the code: 1,438 matched, 262 were overstated, 335 were stubs and 45 had no code. This release fixes the most damaging stubs and security issues and rewrites the matrix to the audited state. Per-item results are in [the M11 audit](../testing/m11-audit/README.md).

- **Security.** OpenVPN server inbounds without configured users (`v1.10.0`–`v1.12.0`) accepted a built-in fixed login and never verified client certificates; nodes without credentials now refuse to start, passwords compare in constant time, and client certificates are verified. Route conditions `in_type`, `in_port`, `dscp` and `uid` used to match all traffic; rules using them now fail to compile. Unimplemented Shadowsocks SIP003 plugins and options used to fall back to plaintext TCP; they now fail at config time.
- **Stubs made real.** Delay probes and background health checks measure an HTTP `HEAD` through the outbound. `SIGHUP`, `PUT /configs` and `POST /restart` replace the running engine, keep it on invalid config and roll back on a failed start. Proxy providers, remote rule sets and geo files download through the chosen outbound with ETag caching and runtime refresh. `/connections` lists live flows and `DELETE` closes them; `/rules`, `/memory` and `/dns/query` return runtime data. The OpenVPN server inbound gains client-certificate auth, an address pool, generated pushes, NCP, rekeying and tls-crypt-v2, verified with official OpenVPN 2.6.20 and 2.4.12 clients. The OpenVPN client's tls-crypt-v2 WKc length is read from the correct end. Mihomo proxies, provider members and share links map per type to kerlico options and reject unsupported fields. `generate mldsa65`/`mlkem768`/`vlessenc` output real keys. `cache.db` no longer loses one of its two writers' data.
- **Behavior changes.** OpenVPN TLS mode requires a certificate and key; default `mtu` is 1500; `keepalive 10 60` applies when unset. Hash32 for `x25519`/`mlkem768` is BLAKE3 (not cross-checked against Xray source). Old top-level Fake-IP entries in `cache.db` are not read.
- **Not yet fixed.** DNS pipeline, binary `.srs`/`.mrs` and runtime geo data, ACME, server-side ECH, sing-mux wire compatibility, dialer options on all protocols and TUN automation remain listed in the audit for later releases.
