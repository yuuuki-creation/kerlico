# 1.1.0 发行说明

## 新增

- **规则路由**：配置 `routes` 按域名、CIDR、端口、网络、节点和用户选择命名出站，见[配置接口](../interfaces/config.md)。
- **WARP 补齐**：配置 `device` 后，`dual-stack` 节点的 `direct` 流量可经 Cloudflare WARP 访问本机缺失的地址族。
- **DNS 与错误事件**：`kerlico history --kind events` 查询，配置项 `dns_records`、`error_records` 分别控制，见[统计历史](../interfaces/history.md)。
- **使用指南**：[中文](../usage.md)、[English](../usage.en.md)。

## 限制

- 多目标 UDP 关联固定走节点绑定的出站，规则只作用于 TCP 和固定目标 UDP。
- `ip_cidr` 只匹配字面 IP，路由不查询 DNS。
- WARP 数据面用已保存身份在双栈机器上验证过；CLI 在真实单栈机器上的自动补齐尚未实测。
- 统计数据库升级到版本 2，旧程序无法打开新库。

## English

- **Rule routing**: `routes` chooses a named outbound by domain, CIDR, port, network, node and user.
- **WARP fill-in**: with `device` configured, `direct` traffic from `dual-stack` nodes can reach a missing address family through Cloudflare WARP.
- **DNS and error events**: query with `kerlico history --kind events`, controlled by `dns_records` and `error_records`.
- **Usage guide**: [English](../usage.en.md), [中文](../usage.md).

Limits: multi-target UDP associations always use the node's outbound. `ip_cidr` only matches literal IPs because routing never queries DNS. The WARP data path was verified with a saved identity on a dual-stack machine; automatic fill-in through the CLI has not been exercised on a real single-stack machine. The statistics database moves to version 2, which older binaries cannot open.
