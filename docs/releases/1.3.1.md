# 1.3.1 发行说明

修复 1.3.0 发布后复查发现的问题。建议所有节点升级。

## 修复

- **远端数据报能让节点停止**：SS2022、Shadowsocks、ShadowsocksR 节点收到停用成员的一个 UDP 包后，整个节点退出，TCP 也一起断开。此前所有版本都受影响。现在该包记为丢弃，节点继续运行。
- **ICMP 错误和发送失败**：节点 socket 上的 ICMP 错误、WireGuard 节点的回复发送失败也只丢弃当前包，不再结束节点。
- **Tailscale 直连握手**：握手洪泛下两套限速器发出不同的 cookie，对端的直连握手无法完成。现在共用一个限速器。此问题由 1.3.0 引入。
- **ZeroTier 入网**：伪造的 HELLO 声明目标地址时，真实的 WHOIS 应答会被丢弃。现在按完整身份去重。此问题由 1.3.0 引入。
- **`require_remote_eof`**：1.3.0 的校验会拒绝规则实际到不了该入口的合法配置。现在按入口的固定目标算出实际选中的出站再判断。

## 计数变化

SS2022 节点的 UDP 丢包现在都计入节点的 `dropped`，包括解密失败、会话和目标上限、重放与队列满。此前这些丢包没有计数。

## English

Fixes from the review after 1.3.0. All nodes should upgrade.

- **A remote datagram could stop a node.** One UDP packet from a disabled member stopped an SS2022, Shadowsocks or ShadowsocksR node, TCP included. All earlier versions are affected. The packet is now dropped and the node keeps running.
- **ICMP errors and send failures.** ICMP errors on a node socket and WireGuard reply send failures now cost only the current packet.
- **Tailscale direct handshakes.** Under a handshake flood, two rate limiters issued different cookies, so a peer's direct handshake could not complete. They now share one limiter. Introduced in 1.3.0.
- **ZeroTier joining.** A forged HELLO claiming a wanted address discarded the real WHOIS answer. Checks now dedup on the full identity. Introduced in 1.3.0.
- **`require_remote_eof`.** The 1.3.0 check refused valid configs whose rules could never reach that inbound. It now uses the outbound actually selected for the inbound's fixed target.

SS2022 UDP drops now all count in the node's `dropped`.
