# 1.3.2 发行说明

修复三台 worker 实机测试查出的问题。最重要的是 Shadowsocks 和 SS2022 的 TCP 数据截断，建议所有用户升级。

## 修复

- **Shadowsocks、SS2022 丢数据**：加密写端在底层写 Pending 后，下次按传入的新长度确认，多出的明文被丢弃，连接随后停滞。节点和出站都受影响，此前所有版本都有。
- **Sudoku 分离传输丢尾部数据**：客户端复用了官方节点写完即关闭的下载连接，并发流偶发丢失尾部，应用只看到正常 EOF。
- **Mieru TCP 全双工断流**：载体读取没有背压，会话缓存超过 256 KiB 就被中止。现在缓存到一半就停读。
- **WireGuard 与用户态栈丢包死锁**：smoltcp 超时回退后，纯 ACK 带旧序号，两端都用 kerlico 时互相丢弃 ACK，60 秒后断开。补丁在 `third_party/smoltcp`。
- **TrustTunnel H3 1 MiB 必断**：设备拒绝 GSO 后，HTTP QUIC socket 包装仍缓存旧的段数，发出的包全部被丢弃。MASQUE 共用此包装。
- **Sudoku mux 大流被重置**：读写共用任务时写的份额过大，33 MiB 约半数失败。现在下行分到更多份额。上传持续快于目标读取时重置仍会发生，官方和 Mihomo 相同。
- **Sudoku 分离传输上行慢**：每次写入发一个 POST，RTT 250 毫秒时约 10 KB/s。现在合并排队写入，stream 约 0.13 MiB/s，poll 约 0.04 MiB/s。
- **Snell 出站**：接官方 snell-server 时，IPv4 目标的 UDP 没有回包，因为回包来源是 IPv4 映射地址。
- **QUIC 客户端退出码**：高延迟路径上收到 SIGTERM 后可能退出码 1。现在只等 200 毫秒发出 CONNECTION_CLOSE。TrustTunnel H3 关闭时不再丢失该帧。

## 测试

30 个协议模块都在 `perf-01`、`perf-02`、`perf-03` 上做了跨机测试和第三方真实对端互通。记录见 [跨机矩阵](../testing/cross-host-2026-11-03.md) 与 [第三方互通](../testing/peer-interop-2026-11-03.md)。三台的公网高位端口被机器防火墙拦截，跨机用例走 Mesh 地址。

新增工具：`tools/interop_cross_host.py`、`tools/peer_interop_matrix.py`、`tools/netem_lab.py`。

## 已知问题

见 [STATUS.md](../../STATUS.md)。主要有：EasyTier udp 载体跨机断流未定位；MASQUE 一条转发路径的 32 MiB 约 20 分钟后结束，未定位；用户态栈在丢包路径上吞吐很低。

## English

Fixes from real-machine testing on three workers. The Shadowsocks and SS2022 TCP truncation matters most, so all users should upgrade.

- **Shadowsocks and SS2022 lost data.** After a pending write, the encrypting writer acknowledged the longer retry slice and dropped the extra plaintext, and the connection then stalled. Nodes and outbounds are affected in all earlier versions.
- **Sudoku split transport lost trailing data.** The client reused a download connection that the official node closes after writing. Concurrent streams occasionally lost their tail and saw a normal EOF.
- **Mieru TCP full-duplex aborts.** The carrier read had no backpressure, so a session buffer above 256 KiB aborted the session. Reading now pauses at half that size.
- **WireGuard and userspace stack deadlock under loss.** After a smoltcp timeout rollback, pure ACKs carried an old sequence number. Two kerlico ends dropped each other's ACKs and disconnected after 60 seconds. The patch is in `third_party/smoltcp`.
- **TrustTunnel H3 always failed at 1 MiB.** The HTTP QUIC socket wrapper cached the segment count after the device refused GSO, so every sent packet was dropped. MASQUE shares this wrapper.
- **Sudoku mux large flows were reset.** About half of 33 MiB flows failed because writes took too large a share of the shared task. Downloads now get more. Resets still happen when uploads keep outrunning the target's reads, as they do with the official core and Mihomo.
- **Sudoku split transport upload was slow.** Each write sent one POST, about 10 KB/s at 250 ms RTT. Queued writes now merge, giving about 0.13 MiB/s for stream and 0.04 MiB/s for poll.
- **Snell outbound.** UDP to IPv4 targets through an official snell-server got no reply because the reply source is an IPv4-mapped address.
- **QUIC client exit code.** SIGTERM on a high-latency path could exit with code 1. The client now waits 200 ms for CONNECTION_CLOSE to leave. TrustTunnel H3 no longer loses that frame.

All 30 protocol modules were tested across machines and against real third-party peers. Cross-machine cases use Mesh addresses because the machine firewalls block public high ports.

Known issues are in STATUS.md. The main ones are EasyTier UDP carrier stalls across machines, a MASQUE forwarding path that ends after about 20 minutes, and very low userspace stack throughput on lossy paths.
