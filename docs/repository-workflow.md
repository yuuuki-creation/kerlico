# 文档、状态、决策与参考资料约定

更新日期：2026-11-02（Asia/Shanghai）

本文说明仓库内各类 Markdown 文档的职责边界与维护方式。

## 存放位置与唯一职责

| 路径 | 核心职责 | 维护原则 |
| --- | --- | --- |
| `README.md` / `README.en.md` | 项目概览、快速开始与主文档入口 | 保持简明，不重复堆叠详细进度流水或完整设计全文 |
| `AGENTS.md` | 协作准则、匿名要求、核心架构约束与测试环境规范 | 维护当前有效规则，不保留已失效的历史停点堆叠 |
| `STATUS.md` | 项目实时进度、测试结果汇总与待完成项 | 进度的唯一主入口；区分已编写源码与已验证范围 |
| `.gitconfig` / `.githooks/` | 固定匿名 Git 身份与提交/推送隐私校验钩子 | 仓库级生效，不修改全局 Git 配置 |
| `docs/README.md` | 架构与设计文档导航 | 提供阅读索引，不另建独立进度表 |
| `docs/*.md` | 目标架构、核心契约、数据路径、生命周期与模块规范 | 按主题单一位置维护，反映最新确认的架构设计 |
| `docs/interfaces/*.md` | 当前源码已实现的公共 API、JSON v2 配置与各协议契约 | 与实际代码保持一致，修改公开签名或配置字段时同步更新 |
| `docs/testing/*.md` | 各协议模块与集成批次的实际测试环境、对端版本与结果记录 | 如实记录通过项、参考对端限制与已知失败 |
| `docs/decisions/*.md` | 重要架构与工程决策的背景、备选方案、取舍与确认状态 | 按编号保存决策演进，用法见 [decisions/README.md](decisions/README.md) |
| `reference/` | mihomo、sing-box、Xray-core 的固定源码调研、横向报告与[借鉴映射](../reference/design-map.md) | 引用固定发行标签与提交 SHA |
| `reference/.upstream/` | 按需下载的上游只读源码本地缓存 | 由 `.gitignore` 忽略，不提交、不纳入本项目编译依赖 |

## 维护与更新原则

1. **单一事实来源（Single Source of Truth）**：
   - 项目进度统一在 [STATUS.md](../STATUS.md) 更新；
   - 目标架构在 `docs/*.md` 维护，当前代码接口在 `docs/interfaces/*.md` 维护；
   - 协议与组合范围统一在 [三核心协议与组合总表](../reference/reports/三核心%20协议%20组合支持.md) 维护。
2. **清晰区分状态，避免防御性赘述**：
   - 使用结构化表格或明确的状态标签（如“已实现”“已验证”“待编译验证”“规划待实现”）直接标明边界，不在每个段落末尾重复免责套话。
   - 历史设计变更的原因记录在 `docs/decisions/` 中，正文直接呈现当前有效方案，不在设计文档顶部堆叠历史变更流水。
3. **上游借鉴规范**：
   - 借鉴上游设计时，按“问题 → 固定源码证据（Tag + SHA + 文件行号）→ 取舍 → Rust 所有权与异步表达 → 验证目标”记录在 `reference/` 与 [借鉴映射](../reference/design-map.md) 中。
   - 若直接引入或修改第三方源码/补丁（如 `third_party/` 或 `vendor/`），须保留原许可证、版权声明与 `PATCHES.md`/`MODIFICATIONS.md` 说明（见 [许可说明](licensing.md)）。
