# 强制匿名提交约定

状态：用户明确要求的仓库约束。日期：2026-10-30。

## 固定身份与范围

作者与提交者均固定为 `Anonymous <anonymous@example.invalid>`。此邮箱仅是匿名占位值，不使用个人姓名、昵称、个人域名或平台账号关联地址。提交与标签的个人签名关闭。

提交内容、说明、文件名、协作者信息和可发布产物均不得包含个人信息。路径使用仓库相对路径或中性占位符；示例使用合成数据。禁止加入自动协作署名 trailer，不使用个人机器产生的原始日志、截图或配置作为未经脱敏的资料。

上游使用固定项目链接和提交号追溯来源。完整上游缓存不提交；以后若涉及带个人署名的第三方材料，不能通过删除必要来源或许可信息伪装匿名，应先解决引入方式和匿名要求的冲突。

## 本地配置与克隆后的启用

可审查的固定配置在根 `.gitconfig`，本仓库 `.git/config` 通过相对 include 加载它，不修改全局配置。Git 不会因克隆了该文件就自动加载它；新的本地副本在任何提交前先执行：

```sh
git config --local include.path ../.gitconfig
```

提交时同时显式指定作者与提交者，覆盖外部环境变量，并禁止签名：

```sh
env GIT_AUTHOR_NAME=Anonymous GIT_AUTHOR_EMAIL=anonymous@example.invalid \
    GIT_COMMITTER_NAME=Anonymous GIT_COMMITTER_EMAIL=anonymous@example.invalid \
    git -c commit.gpgSign=false commit --no-gpg-sign
```

命令本身不是提交授权；只有当前任务已要求提交时才执行。合并、补丁应用、变基、拣选和 amend 也必须满足同一规则，不将上游个人作者历史合并进本项目。

Git 环境变量可以覆盖配置，因此配置之外还检查实际身份。依据：[Git commit information](https://git-scm.com/docs/git-commit#_commit_information)。

## 校验钩子

- `pre-commit` 检查实际作者/提交者、签名默认值、分支名与完整暂存快照。
- `prepare-commit-msg` 再检查身份与暂存内容，防止普通提交流程跳过前一检查。
- `commit-msg` 检查最终说明、邮箱、署名 trailer 和明显敏感信息。
- `pre-push` 检查待发布引用的可达历史、作者/提交者、标签署名、签名对象及历史文件内容，不只检查最新提交。

检查实现集中在 `.githooks/privacy-check`，需要 Git、shell 和 Python 3；检测结果只显示类别，不回显匹配到的个人信息。当前拒绝未经审查的非 UTF-8/二进制内容、子模块和明显敏感文件；以后支持其他产物时需先设计相应检查，不能直接绕过钩子。

检测覆盖非匿名邮箱、个人目录格式、本机登录名/全名/主机名、常见身份 trailer、密钥、凭证 URL 和部分 token 格式。自然语言中的任意人名和未知格式信息仍需人工复核；自动扫描不能证明世界上所有个人信息都已被识别。

钩子在本地执行，可以被有权限的人修改或通过其他 Git 操作绕过，因此禁止禁用、替换或跳过检查。显式签名选项等情况还需核对最终对象；推送钩子会拒绝携带签名的对象。Git 钩子触发与退出行为依据：[githooks](https://git-scm.com/docs/githooks)。

## 每次提交与发布

先审查完整暂存快照、文件名和最终说明，再检查实际作者与提交者。操作完成后核对新提交对象，确保身份为固定值、说明无个人信息且不存在签名；发现问题先修复，不继续发布。不擅自重写别人或已共享的历史。

发布还须检查全部拟发布的提交与标签。Git 作者名与平台认证账号是不同信息，修改 author 不会匿名化远端账号、网络地址或平台日志。用户已明确指定公开发布目标 `yuuuki-creation/kerlico`，该命名空间可以用于授权的远端 URL；作者与提交者仍保持固定匿名身份。发布进度以 [STATUS.md](../STATUS.md) 和实际远端状态为准。
