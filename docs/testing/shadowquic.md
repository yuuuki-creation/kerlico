# ShadowQUIC 验证记录

日期：2026-10-31。QUIC v1 双端的限定组合已通过固定 Mihomo；v2 通过字节向量、Rust 双端与受控独立 Go 参照。原固定 Mihomo v2 被标准参数校验拒绝，仍未登记原资产兼容。

## 环境与检查

所有构建、格式、Clippy、Rust 测试和互通均在 `perf-03` 的独立项目工作区运行，构建并发为 1；本地只编辑、阅读、同步和仓库管理。两个受控依赖排除 workspace 的独立目标检查，但随本协议实际编译并通过使用路径回归；未声称通过它们完整上游测试集。

包级格式、10 个修改过的依赖 Rust 文件格式、严格 Clippy（`--all-targets -- -D warnings`）、ShadowQUIC-only CLI 和合成普通 QUIC 上游构建通过。最终包级复验为 16 项测试：1 项编解码、8 项双端、3 项原始对端、4 项固定向量。没有运行完整工作区或发行检查。

## 固定真实对端

复用按官方发行资产摘要核验的 Mihomo v1.19.33，SHA256 为 `817f50b3ac6a8b1c4360c5cf2961906057f3a883d970ebbcb0028a01632b620f`。互通工具为 `tools/interop_shadowquic.py`；只启动回环代理、目标及合成 QUIC 上游。官方资产来源核验记录沿用 TUIC 私有管理记录，未以版本字符串代替来源认证。

- QUIC v1：两角色 × 两 UDP 模式 × 两节点地址族 × 三种本端拥塞，24/24 配置、72/72 项 TCP/UDP/实际回退检查通过。TCP 为 257024 字节；datagram 为 17/900 字节；stream 为 17/1200/12000 字节。普通 QUIC 探测只信任合成上游证书，实际握手/回写证明回退。
- QUIC v2：24/24 配置在 TCP 建立时复位，不能登记通过。固定 `jls-quic-go 732f2fc9a34d` 未实现 `version_information`，与 RFC9369 §4 的强制要求不符；本端保持拒绝。独立合成 JLS 握手诊断中，同一 Mihomo 节点 v1 成功，v2 明确返回 `VERSION_NEGOTIATION_ERROR=0x11`，与固定源码证据一致。
- v1 生命周期补充：IPv4 节点/cubic、两角色 × 两模式，4/4 配置、16/16 项 TCP/UDP/真实回退/有界退出与重启检查通过。

真实结果保留为完整 48 配置运行的 24 成功、24 失败，未把失败筛掉后声称全矩阵通过。下文受控独立 ShadowQUIC 参照结果单列，不能归于原官方二进制。不能通过省略标准强制参数校验换取兼容。

## 单列受控 Go 参照

`tools/shadowquic_reference_peer/` 提供可复现构建、合成双角色入口、两个规范补丁及单独的恶意参数补丁；只作为专用 worker 对端，不进入 Rust 内核运行路径。使用固定 Mihomo 传输包，未编译完整控制面；Go 1.26.10 工具链只存放项目内，构建并发/GOMAXPROCS 为 1，Go 堆软预算 768 MiB。固定来源、许可证、三个改动文件的前后摘要与依赖清单见该目录 `SOURCE.json`。

1. 只补 0x11 的参照：JLS v2 握手成功，完整 TCP 负载触发 Go 首次密钥更新后超时。参照摘要为 `430f2b5151ed7e36d04f0b1fff7ee5922806f17db9524f7b6e2e8fe722e479ac`，源码副本和失败记录保留。
2. 固定源码的更新函数仍使用 `quic ku`，不符合 RFC9369 的 `quicv2 ku`。直接调用该函数的 RFC9001/RFC9369 附录 A.5 固定向量中，旧 v1 通过/v2 失败；追加独立按版本选标签补丁后两者通过。Rust 正确标签、257024 字节 TCP 负载与原首次更新门槛保持不变。
3. 最终受控 v2：两角色 × 两模式 × 两节点地址族 × 三种本端拥塞，24/24 配置、72/72 项 TCP/UDP/真实回退检查通过，包长与原矩阵一致。双方向额外完整负载检查均成功且实际日志观察到 KeyPhase=1，共 2 配置、6 项数据/回退检查及 2 项更新事件断言。
4. 独立负例：Go 参照通过链接参数分别省略 0x11、在 v2 上发送自洽 v1 参数；两发起角色 × 两节点地址族 × 两故障，共 8/8 组均返回 0x11，且每组同节点的合法控制组握手成功。恶意变体只存在测试副本；正常参照也校验对端参数。
5. 生命周期：v1/v2 × 两角色 × 两模式，IPv4 节点/cubic，8/8 配置、32/32 项 TCP/UDP/真实回退/有界退出与同端口重启检查通过。
6. 从新目录运行提交的 `build.py` 重建，正常及两个恶意参照的三个二进制摘要均与验收版本一致。工具脚本没有把运行中的业务程序替换为 Go 子进程。
