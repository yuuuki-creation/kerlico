# Mieru 验证记录

日期：2026-10-31。限定交付：**默认 TCP 双端、真实复用及 TCP/Full Cone UDP 包隧道已验；原 UDP 线格式只在显式本机不安全兼容类验收，公网 UDP 未支持。** 原 UDP 的 nonce 复用风险不因任何通过结果消失。

## 环境与快照范围

所有构建、格式、Clippy、Rust 测试和互通仅在 `perf-03` 独立项目区，构建并发 1，本地仅编辑、阅读、同步和 Git 管理。首次完整编码后才统一构建与集中修正。私有清单裁剪为 core/config/net/egress/engine/Mieru 和真实 app 注册；使用全新 Cargo home/target，排除 Sudoku、SSR 待验修正及 ShadowTLS HRR 变体。没有验证当前完整工作区、release 或其他平台。

鉴权与隔离契约按两个集合处理：TCP auth 基于真实基础秘密；本地 UDP auth 空，不能因此取得 `nodes` 资格；两载体 isolation 同时包含 `mieru` 秘密和 `mieru-user` 身份域。Mieru 同名异密、同实际凭据跨载体、不同身份三类边界已分别测试。公共契约另见[独立回归](credential-isolation-contract.md)。

## 原 UDP 密码学证据

`tools/mieru_nonce_probe` 在固定官方 v3.38.1（`a2208ee7a38fb41d843a13ecdde858e67ef2f485`）和 v3.39.0（`bcd14b88d0fb7e7707bb80e5d7f6c33675d26c06`）cipher API 上，用合成凭据/hint/数据复现同段元数据与负载使用相同 key/nonce。两版本均满足密文/明文异或关系；知道 32 字节合成元数据时，从两段密文恢复 32 字节合成负载前缀。TCP 递增 nonce 控制组不满足该关系。运行期未联网、未做认证伪造或攻击真实服务。

该模式仍须 `unsafe_udp_compatibility=true`、IP 字面回环和 `local_inbounds`，auth 为空。来源/探针/二进制摘要见 `tools/mieru_nonce_probe/SOURCE.json`；不以密码字段或互通成功宣称可靠公网鉴权。

## 三套独立对端

官方 API 小程序只调用固定源码双角色 API；构建校验全部非测试 Go 文件前后未变。项目内 Go 1.26.10、单并发、768 MiB 堆软预算，没有 Go 业务子进程进入 kerlico。Mihomo 原资产复用已按官方发行摘要核验的 v1.19.33，不以版本字符串替代来源认证。

各套完整矩阵为：基线 32、低熵 48、额外 IPv6 网站目标 8，共 88 配置；TCP 257024 字节，常规 UDP 17/1200/12000。每配置有 TCP/UDP 两项检查。

| 参照 | TCP 载体 | 仅本地不安全 UDP 载体 | 常规合计 |
| --- | --- | --- | --- |
| 官方 API v3.38.1 | 44/44 配置，88 检查 | 44/44 配置，88 检查 | 88/88，176/176 |
| 官方 API v3.39.0 | 44/44 配置，88 检查 | 44/44 配置，88 检查 | 88/88，176/176 |
| 原 Mihomo v1.19.33 | 44/44 配置，88 检查 | 44/44 配置，88 检查 | 88/88，176/176 |

三套合计 264 配置/528 常规检查；不是公网 UDP 验收。每套另有两角色/两载体、IPv4 节点/mux/等待模式的 4 配置、12 项有界退出与同端口重绑检查，合计 12 配置/36 项通过，没有跨重启会话迁移结论。

### 空包与大包按参照分列

两版官方 API 各 8/8 个空包/65507 探测通过，后续小包恢复通过。API 入口直接复用官方 PacketOverStreamTunnel 和地址解析，以 `io.ReadAll` 保留零 payload；没有声称原 `UDPAssociateWrapper.ReadFrom` 或原 Mihomo 客户端也能处理它，后者在源码中可返回 EOF。

原 Mihomo 的基线包长结果（IPv4 节点及网站、两外层载体结果一致）：

| 本端角色 | 已测通过 | 明确失败或未验收 |
| --- | --- | --- |
| kerlico 客户端 → Mihomo 服务端 | 空包、16362、16374 字节 | 16384/16385/65507 未返回，不能外推中间未测长度 |
| Mihomo 客户端 → kerlico 服务端 | 16362/16374/16384 字节 | 空包失败；16385 实际回 16384；65507 内容/长度不符 |

较细包长运行有 4 配置/8 项常规检查、16 项边界探测（10 通过、6 失败），失败后均复验小包恢复。固定 Mihomo 标准 UDP 池为 16 KiB，与上述限制相符；这是来源解释，不把未测边界或 IPv6 最大包长写成已验。内核与独立 API 的 65507 结果单独保留。

## 首轮失败与修正保留

API v3.38.1 首轮是 86/88 配置、172 常规检查通过，两个失败集中于本地 UDP 低熵32客户端接收 257024 字节回包。限定观测自有进程 UDP socket：重复可完整返回，但曾丢 29/20 包，队列接近默认上限；Go 参照无丢包。worker rmem_default/rmem_max 均为 212992。

集中修正只为本项目 socket 请求 2 MiB SO_RCVBUF（系统可截断）、通告接收窗口最多32，保留乱序128/待发512容量；没有改 sysctl、减 payload 或改 nonce/key。两定点复验均完整回包且观测 drops=0，随后三套完整矩阵通过。原失败、采样及复验均保留。

Clippy 四处库写法/类型问题和两处测试导入/循环问题已修正并限定复验。私有 Mieru-only 清单首次误删基础 workspace 依赖的裁剪问题也保留记录；修正测试清单后真实 app 注册构建通过，没有用测试副本改写共享根/app 实现。
