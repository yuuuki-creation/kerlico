# sing-mux 互通记录（2026-11-07）

结论：kerlico 的 smux、yamux、h2mux 在有无填充、Shadowsocks 与 VLESS 载体下，与 sing-box 1.14.4、Mihomo v1.19.33 双向互通，48 个 kerlico 格与 24 个 sing-box / Mihomo 基线格全部通过。

## 环境与命令

`perf-01` 回环，参考二进制取官方发行包：sing-box 1.14.4（sing-mux `caf09fe`）、Mihomo v1.19.33（metacubex/sing-mux v0.3.12）。kerlico 为本分支 release 构建。

```sh
tools/worker_run.sh perf-01 'cargo build --release -p kerlico && python3 tools/interop_sing_mux.py \
  --kerlico "$CARGO_TARGET_DIR/release/kerlico" --sing-box <sing-box> --mihomo <mihomo> --baseline --out result.json'
```

每格三项检查：

1. 经 SOCKS5 CONNECT 的 1 MiB 随机数据 TCP 回显，逐字节比对。
2. 经 SOCKS5 UDP ASSOCIATE 的 20 个 1 到 1400 字节数据报回显，逐字节比对。
3. 32 路并发流同时保持打开时采样载体 TCP 连接数，再各回显 64 KiB。客户端 `max_connections 4`、`min_streams 4`，要求载体连接峰值在 1 到 4 之间。

填充格的服务端要求填充。检查结束后两端进程须仍在运行。

## 过程中修正的问题

- 首轮 kerlico→sing-box 的 12 格 UDP 全部失败，其余 36 个 kerlico 格通过。原因：逐包地址 UDP 流的请求目标写成占位的 `sp.mux.sing-box.arpa:444`，sing-box 服务端按请求目标路由整条 UDP 流，因此不转发任何包。改为随首包写出请求、目标取首包目标（与 sing-mux `ListenPacket` 一致）后，12 格全部通过。
