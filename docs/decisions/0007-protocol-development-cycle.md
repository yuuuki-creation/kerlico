# 0007 协议开发固定顺序

状态：已确认。日期：2026-10-30。

用户要求当前 VLESS 及之后每种协议都按“调研 → 编写 → 测试 → 修改”推进，第一次必须一口气写完代码。该要求调整 0002 中“实现并验证一个最小组合后进入下一项”的开发顺序；支持总表、固定证据和独立记录组合结果的规则保留。

1. 调研：明确本轮协议的完整交付范围、角色、合法组合、依赖及验收矩阵。
2. 编写：集中写完上述范围的实现、配置接线与接口文档，再进入测试阶段；不逐段编译或测试。
3. 测试：在专用 worker 按 [0012](0012-simplified-delivery-and-verification.md) 执行。
4. 修改：集中修复，复跑受影响 crate。

所有提交保持匿名，文档与说明使用简体中文；编译和测试只在 worker 执行。
