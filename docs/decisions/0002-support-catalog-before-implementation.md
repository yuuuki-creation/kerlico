## 当前决定

先以固定版本源码、注册表、构造和关键运行检查形成[协议与组合总表](../../reference/reports/三核心%20协议%20组合支持.md)，保存角色、版本、构建条件、组合限制与未知项。该文件是协议/组合清单的唯一主入口；其他文档引用其稳定编号，不重复维护独立清单。

保留框架先行和逐项开发：获得明确实现指令后先验收最小框架，再选择一个角色和最小组合，补齐当前任务所需的规范、实现细节、依赖、许可证与测试研究，完成实现和验证后进入下一项。集中目录研究不等于提前完成所有握手、算法或平台审查。

## 取舍与边界

集中支持清单能先暴露跨核心差异，减少按协议名称误判兼容的风险；代价是资料有版本边界，开工前仍需复核。构造接受、运行路径、互通实测和 kerlico 实现状态分别记录，不用一个“支持”勾选合并。

本决定不将上游联合目录全量列为 kerlico 目标，不确认首批平台、角色、优先级或库选型，不授权本轮建立 Cargo 工程或编写实现。资料未经过本轮构建、上游运行、互通或性能测试。

## 影响与验证

总表保存协议/组合观察和建议任务，路线文档只保存阶段，STATUS 保存汇总进度。AGENTS 与资料维护约定采用本流程。0001 保留为历史，不删除其中的原始讨论依据。

当前验收是总表可追到固定来源、角色和限制不丢失、未知项明确且导航一致。未来每项标为已验证时，还需实际提交、工具链/平台、对端版本、具体组合、命令/条件和测试结果。
