## 文件命名

使用 `0001-short-topic.md` 这类稳定编号与简短主题名称。编号只用于定位，不代表优先级。README 是使用说明，不占编号；链接到记录时优先使用文件路径，不依赖标题文本。

当前不预建空记录，也不因为文档里出现建议就自动登记为已确认。

## 每份记录的内容

- 标题、编号、状态、提出/更新日期。
- 问题和约束：要解决什么，本项目哪些需求已经明确。
- 备选方案：各自收益、成本和适用边界。
- 建议或决定：选择及理由；草案使用“建议”，已确认后才写“决定”。
- 影响：需要修改的设计、兼容性、资源责任和后续工作。
- 依据：借鉴条目、固定源码、标准或实测结果；区分事实与分析。
- 验证目标与实际结果：没有实现时仅列目标，不能填写“通过”。
- 确认或取代关系：用户明确确认的日期与内容摘要，或替代记录的链接。

## 状态

| 状态 | 含义 |
| --- | --- |
| 草案 | 可讨论、可调整，未记录为用户已确认 |
| 已确认 | 用户明确确认该项选择，相关设计与 STATUS 同步 |
| 已采用 | 用户已授权代理在当前任务范围自主决定，并已记录具体选择与依据；不伪称用户逐项确认 |
| 已否决 | 讨论后没有采用，保留理由和适用背景 |
| 已取代 | 曾经确认，后来由另一份记录替代，互相链接 |

同一草案可随讨论修改。已确认的核心选择发生改变时，新建后续记录并标明取代关系；不要把旧记录改写成仿佛从未作过原决定。文字修正或补充准确来源不必新建一份。

工作状态“已实现/已验证”由 [STATUS.md](../../STATUS.md)及相应模块资料维护，不能用“决策已确认”代替。决策确认也不代表用户授权开始编码。
