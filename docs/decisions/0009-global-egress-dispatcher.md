# 0009 全局共享出站调度器

状态：全局共享范围及远端可能有多个代理由用户明确确认；下述接口、分组及选择形态为设计建议，尚未实现或验证。日期：2026-11-01。

本地地址族模式、设备共享WARP及远端原请求透传的责任边界现以[0010](0010-node-egress-modes-and-warp.md)为准；本记录的全局所有权与多代理规模保留。

## 问题与确认范围

用户明确要求所有节点共享同一个出站调度器，出站作为独立模块全局共享。该要求补充[0005](0005-separate-nodes-unified-egress.md)对“统一访问口”的范围，保留独立入站凭据和统一目标访问原则。

用户进一步明确远端可能有多个代理。唯一调度器必须能管理多个并列远端代理，不能把“共享出站模块”实现为所有流量固定访问唯一代理服务器。这一补充不改变共享所有权方案，也不自动确认代理链或具体选择算法。

当前`Registry::prepare`先构造命名出站表，又在节点循环中为各节点重新构造出站；engine再按节点注入持有该出站的Egress。它共享访问实现代码，尚未共享同一个运行调度器。

代码注释说明逐节点重建是为避免认证连接池和票据串用。这解释了原实现的隔离目的，不证明必须复制整个出站模块。新的所有权边界需要保留身份和会话归属，同时消除按节点复制出站的结构。

## 已确认的所有权边界

- 同一个Engine运行实例拥有一个独立出站运行服务和一个共享调度器。这里的全局范围是该运行实例，不要求使用进程静态变量。
- 每条命名出站配置只构造一个运行实例，由出站模块唯一持有。多个节点引用同一出站标签时，进入同一个调度器并使用同一个命名实例。
- 命名表可以同时包含多个远端代理出站，以及直连等已有出站。每个远端代理有各自的协议、端点、认证和传输配置，入站节点标识、远端代理标识和业务目标地址分别建模。
- 入站节点负责监听、协议鉴权、解码和回包封装。鉴权后提交业务目标，节点不持有出站工厂、出站实例或另一套调度逻辑。
- 节点身份、入站认证材料、会话、统计、配额和取消域保持各自归属。共享模块负责其连接及会话资源的必要分区，不能把共享实例理解为认证凭据可以互用或UDP关联可以合并。
- 目标地址族不由入站地址族决定；本节点负责的双栈目标路径默认IPv4优先，远端透传路径执行远端策略，具体按[0010](0010-node-egress-modes-and-warp.md)。TCP、固定目标UDP和同socket多目标UDP关联保留不同的数据模型。

目标流量图统一维护在[节点与统一出站](../node-egress.md#统一访问口)。

## 多个远端代理与选择建议

具体出站实例和出站选择引用分开表达。保留直接引用一个命名出站的能力；若需要从多个代理中选择，建议增加独立的出站组，组只保存已有实例的标识和显式选择策略，不调用出站工厂，也不复制实例。

| 对象 | 语义 |
| --- | --- |
| 具体出站标识 | 指向命名表中的一个直连或远端代理运行实例 |
| 出站组标识 | 指向一组具体出站标识及其选择策略；属于设计建议 |
| 入口选择引用 | 固定出站引用，或出站组引用；由共享调度器解释 |
| 已选出口 | 当前连接或关联选定的具体出站，建立后保持不变 |

建议首版组成员只引用具体出站，不嵌套组或回指调度器，以保持引用关系可校验。请求需要的TCP、EOF、固定UDP或多目标关联能力必须由实际候选提供；不能只合并所有成员的能力后任意选择不兼容的成员。没有符合能力及策略的出口时明确返回失败，不隐式改为直连。

不同新连接可以选择不同代理并并发运行。一个TCP连接、固定UDP通道或多目标UDP关联在建立时固定所选具体出站；多目标关联的逐包目标解析不重新选择代理。回包保留原关联、代理和入站归属，不能把多个代理返回的数据混在同一关联中。

出站组仅作为初始选择的设计建议。用户已在[0010](0010-node-egress-modes-and-warp.md)明确远端失败不由本机补救，本节点不据此换代理、换网站地址族、回退直连或WARP重试，也不把UDP数据广播给多个代理。手动选择、轮询、权重和健康探测等具体初始选择算法尚未确认。

不同远端代理的连接池、认证会话与票据按各自代理配置及必要来源作用域管理，不能只凭协议或网站目标相同合并。单个请求、节点或代理的取消和失败不能终止其他代理上的无关请求；整个出站服务关闭仍由统一运行所有者协调。

网站IPv4/IPv6只在本节点负责的目标路径按节点模式安排，包括原生和设备共享WARP出口。远端分流保留原始目标，由远端自己解析和选择地址族；本机只另行处理代理端点的载体拨号。本记录早先建议对代理网站目标本地选IP，现由[0010](0010-node-egress-modes-and-warp.md)修正。详细规则及当前源码差距统一维护在[目标地址选择](../node-egress.md#目标地址选择)。

## 调用者用法建议

建议保留协议当前的窄目标访问接口。装配阶段向每个节点签发一个轻量访问句柄，句柄只绑定可信入口身份和同一个调度器的引用，不持有出站、解析器、连接池或选择表。

下例是接口草图，不是现有可编译API。

```rust
let prepared = registry.prepare(config)?;
let (egress_runtime, mut access_bindings) = EgressRuntime::start(prepared.egress)?;
let access = access_bindings.take(node.id)?;

let stream = access.connect_tcp(&target, &request_context).await?;
let channel = access.connect_udp(&target, &request_context).await?;
let association = access.associate_udp(&request_context).await?;
```

准备结果将唯一出站表和入口绑定移交出站运行服务。固定目标入口和本地动态入口也应进入同一个服务，避免保留第二条直接访问裸Outbound的路径。

## 数据形状与职责建议

| 对象 | 持有的内容 | 所有者 |
| --- | --- | --- |
| 准备后的出站计划 | 已校验入口标识、出站标识、唯一命名出站及绑定 | 配置准备阶段构造，移交运行服务 |
| Dispatcher | 唯一出站表、入口选择引用、可选出站组、本地/远端分支及本地目标候选安排 | 出站模块 |
| 轻量访问句柄 | 可信入口标识、共享Dispatcher引用 | 引擎签发给相应入站 |
| 出站请求上下文 | 来源归属、本次建立预算、请求及节点取消条件 | 调度器根据可信绑定产生 |
| 出站资源生命周期 | 公共后台资源和身份分区资源的停止、排空及关闭 | 出站模块，由引擎协调关闭 |

出站的共享对象需要接收可信来源上下文，以在内部管理必要的池、票据和关联分区。不能在共享对象里按节点嵌套完整Outbound或再次调用工厂，否则只是隐藏了旧结构。无状态出站不需要人为增加池分区。

节点只拿自己的访问接口，不能从客户端请求中指定另一节点身份或改写出站绑定。该边界面向正常模块装配和网络输入，不声明能隔离任意恶意同进程Rust代码。跨crate构造接口的具体可见性在实现时明确。

## 并发与生命周期建议

共享所有权不要求单线程或单个串行请求队列。命名出站表在装配后只读，各请求并发调用所选实例；池等可变资源按实际作用域同步，不持有覆盖全部拨号的全局锁。

请求取消只影响本次操作及其独占资源。节点强制停止只结束该节点的请求和所属分区，不能关闭整个共享出站。共享后台任务具有出站服务或必要分区的生命周期，不能继承首个请求的取消令牌。引擎结束时统一协调自己拥有的出站资源关闭，不能仅以释放Arc推定所有后台任务已退出；设备共用WARP服务由设备所有者管理，不随单个Engine退出关闭。

保留当前停止接纳后关闭节点逻辑流预算、有限排空再强制取消的语义。目标候选的建立期限不等于已返回流的整个使用期；已发送业务数据不跨候选重放，UDP关联不跨节点或请求合并，回包继续返回原关联及原节点。

## 备选与选择理由

建议采用唯一Dispatcher和身份绑定轻句柄。它保持协议“访问目标”的调用面，把绑定、出站查找、地址候选与资源归属集中在独立模块。

显式逐调用传递可信许可也能实现全局共享，但会将固定身份传播责任扩散到各协议及派生任务。actor方案可以集中所有权，却额外引入邮箱、队列等待和取消竞态；当前没有需要该队列的调度要求，因此不作为首选。

本轮比较了上述结构形态，选择轻句柄方案作为建议，并补充出站公共资源与节点分区的生命周期。该选择不是用户对每个内部类型的逐项确认。

## 影响与迁移范围

配置层删除逐节点工厂重建，节点仅保留可信身份及出站绑定引用；准备结果不向调用方开放可以绕过调度器的运行出站表。egress统一拥有调度及命名实例；engine只装配一次服务并向所有入口注入访问接口。core-api需要表达出站请求归属及生命周期；有状态协议出站需要将原来依赖实例隔离的状态改为明确作用域。

迁移时一并移除旧的按节点Egress包装和固定入口裸Outbound调用路径，不能长期维护两套访问机制。多个远端代理属于目标规模；出站组及算法仍是建议，本要求不自动扩展为规则路由、负载均衡实现、代理链、DNS缓存、独立DNS服务或热重载。

## 验证目标与当前结果

后续在授权worker验证同标签构造一次、所有入口进入同一调度器、多节点与多代理并发、能力不匹配的候选被拒绝、连接及关联的出口固定、节点及首个请求取消不影响其他请求、三类I/O的回包归属和资源关闭。具体协议的有状态资源需要分别复核，不能从Send+Sync或签名通过推定已满足共享生命周期。
