# 0009 全局共享出站调度器

- **状态**：已确认（唯一 `EgressRuntime` / `Dispatcher` 与多命名远端出站已合入主工作树；出站选择组待实现）
- **日期**：2026-11-01（2026-11-02 更新状态）

## 背景与约束

- 用户明确要求：所有节点共享同一个出站调度器，出站作为独立模块全局共享；同时远端可能有多个并列代理。
- 早期实现中，`Registry::prepare` 为每个节点重复构造 `Outbound` 实例并注入节点私有的 `Egress` 包装，虽然复用了代码，但未共享运行期调度器与出站实例。
- 新设计需消除逐节点复制出站的结构，同时保持入站节点的凭据隔离、会话归属、配额与取消域独立（本地节点模式与远端原目标透传边界见 [0010](0010-node-egress-modes-and-warp.md)）。

## 决定与所有权边界

1. **单 Engine 唯一调度器**：同一个 `Engine` 运行实例只装配一个 `EgressRuntime` 与一个共享 `Dispatcher`。
2. **命名出站一次构造**：每条命名出站配置在运行期只构造并启动一个运行实例（`RunningService`），由 `Dispatcher` 统一持有；多个入站节点引用同一出站标签时共享同一运行实例。
3. **支持多个并列远端代理**：命名出站表可同时管理多个远端代理实例及本地直连/拒绝实例，各远端代理独立维护自身的协议、端点、认证与传输配置。
4. **轻量绑定句柄交接**：入站节点仅持有绑定节点身份的 `IngressBinding`，完成协议鉴别后签发 `PeerSession` 向共享 `Dispatcher` 提交请求，节点自身不持有 `Outbound`、解析器或连接池。
5. **连接固定与池隔离**：每个 TCP 连接或 UDP 关联在建立时固定所选命名出站，已交付业务数据不跨代理重放；有状态代理的连接池与会话票据按 `ResourceKey`（命名出站 + 来源成员/Local + 凭据代次）分区管理。
6. **分层取消生命周期**：单请求取消、单 Peer 取消、单节点取消与共享命名服务关闭分别处理；单个节点停止不关闭共享出站服务。

## 多个远端代理与出站组建议

| 概念 | 职责与边界 |
| --- | --- |
| 命名出站标识 (`OutId`) | 指向命名出站表中的具体运行实例（已实现） |
| 出站组（Policy Group） | 引用一组已有命名出站标识并执行初始选择策略，不重复调用工厂构造实例（规划待实现） |
| 已选出站绑定 | 单次 TCP 连接或 UDP 关联建立时固定所选的具体出站，存活期内不跨代理切换 |
