# 0006 客户端与服务端一体

状态：已确认架构方向，尚未完成双端实现。日期：2026-10-30。

## 决定与依据

用户在明确 mihomo 可承担客户端与代理服务端后，要求本项目也做成一体。继续使用一个 Rust 可执行程序、共享核心和按协议独立的模块，按配置装配客户端路径、服务端路径，或同时运行两者。沿用 [0005](0005-separate-nodes-unified-egress.md) 的节点凭据与统一目标访问约定。

## 角色和路径

| 用法 | 目标路径 |
| --- | --- |
| 客户端 | 本机应用 → 本地接入或 TUN → engine → 统一目标访问服务 → 协议出站 → 远端代理 |
| 服务端 | 远端客户端 → 协议入站节点 → engine → 统一目标访问服务 → 直连或配置的上游出口 → 目标服务 |
| 同时运行 | 同一程序配置多种入站和出站；每个实例保留自己的身份、配置及生命周期，流量按明确规则分发 |

客户端的本地接入、服务端的协议接入和所选出口属于不同角色。一个协议 crate 可以同时提供入站、出站，共享编解码与规范相关逻辑；鉴权状态、节点凭据和连接使用期按实例持有。某协议只实现一个方向时，只声明该方向。

统一目标访问服务通过 core-api 契约供接入路径调用；具体出站由它按决策选用。协议出站使用底层连接器建立载体，不能将同一个目标再次无条件提交给自身的业务入口。两个角色共存需要检查配置引用和解析/拨号依赖环。

## 保留的约束

服务端 IPv4、IPv6 节点分别建立，认证凭据独立。目标地址选择交给统一访问服务，默认优先 IPv4，目标地址族独立于节点接入地址族。TCP 与 UDP 使用各自的流/包接口。编译与测试全部在专用 worker 执行，提交继续匿名并使用简体中文。

一体化不自动提供每个协议的全部角色、TUN/IP 隧道、同端口协议分流或所有平台支持。这些能力依照总表和接口逐项实现、验证后登记。

## 当前差距与验收

已有固定转发入口和普通 VLESS 客户端出站，另有未发布的组合开发内容；服务端节点鉴权、统一目标访问模块和完整 VPN 接入仍需实现。总表保留既有稳定编号，后续角色分开记录，既有出站结果不外推入站。

验收分别覆盖客户端连接真实参考服务端、服务端接收真实参考客户端、双角色共存且无调度循环、节点凭据隔离、IPv4 优先及目标可达性、取消和资源回收。此处记录验收目标，没有新增通过结论。
