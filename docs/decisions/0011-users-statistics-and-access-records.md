# 0011 多用户、流量带宽与访问记录

状态：用户明确确认需求范围，适配模型和实现参数仍为建议，尚未实现或验证。日期：2026-11-02。

## 确认依据

用户要求一个节点允许多个用户，各自有用户名和密码，用户名默认附UUID防止重名。每个用户需要保存带宽使用、上下行流量，以及域名和IP等访问记录。用户进一步确认按Xray日志与统计的分离方式处理，流量、带宽均要具备，Xray相关能力适配本项目结构。

确认的Xray参照范围是本轮已核对的访问/错误/可选DNS日志、按用户及入出站的流量、在线来源、查询导出和日志输出控制，不把一句要求扩大为Xray全部产品功能。研究来源见[固定源码研究](../../reference/research_notes/xray-statistics-and-access.md)。

## 保留的架构约束

[0009](0009-global-egress-dispatcher.md)的唯一Dispatcher和每命名出站一次构造、[0010](0010-node-egress-modes-and-warp.md)的本地模式/设备WARP及远端原目标透传继续有效。统计不能迫使节点复制出站，也不能为记录远端网站IP而在本地解析或改写网站目标。

节点凭据域继续独立。统一用户账户不意味着所有协议线格式都含用户名密码，不意味着允许跨节点复用协议秘密。管理ID、显示用户名和协议认证材料需要分开。

## 适配建议与取舍

建议每个Engine共用一个统计运行服务，协议鉴权后将可信用户及节点归属绑定到逻辑会话和UDP关联，贯穿共享Dispatcher。业务载荷选择唯一计量边界，再按用户、节点、实际出站和Engine总量投影。载体与设备开销另列，不按共享物理连接猜测用户分摊。

流量表示累计字节，带宽表示指定时间窗口内的速率。当前、平均和采样峰值分别定义，保留采样质量与历史桶。在线用户、来源IP、物理连接和逻辑会话有各自语义，旧接纳/结束事件不能直接换名使用。

访问记录与用量汇总独立，通过用户、节点和会话标识关联。保留原目标、已知业务连接IP和代理端点的区别，记录结束与该次用量。数据库或文件中的历史用量不随运行计数或查询基线清零而删除。

与仅增加节点原子字节计数相比，这一设计需要可信用户上下文、统一计量、历史存储与查询契约，改动更广，但能支持共享出站与多用户归属。只解析Xray样式日志文本无法补出其本来没有的结束用量，也无法可靠恢复多协议身份，因此不作为统计依据。

完整字段、口径、计量边界与故障建议统一维护在[多用户与统计](../statistics-and-users.md)，本记录不另存一套参数。

## 未确认项与当前差距

用户跨节点授权与额度合计、限速/配额/计费、到期及禁用会话处理尚无具体产品规则。存储后端、采样频率、保留期限、查询协议和JSON字段仍需细化。目标能力统计不等于已实现限速或精确计费。

现有部分协议有多凭据，但公共上下文没有稳定的管理用户归属；公共统计仍只有四类节点事件。新统计服务、流量、带宽、在线与访问历史均未完成迁移。实际签名和旧验证保留在接口与根STATUS。
