# 0005 节点分别建立，目标访问统一

状态：节点与目标分离原则保留；共享范围由[0009](0009-global-egress-dispatcher.md)补充，本地模式、设备WARP与远端透传由[0010](0010-node-egress-modes-and-warp.md)明确。原记录日期：2026-10-30；补充日期：2026-11-01。以下原始实现差距和验证目标属于当时记录，不代表当前实现状态。

## 用户澄清与取代关系

用户明确：建立节点时 IPv4、IPv6 分开建立，二者凭据分开；所有协议的节点通过统一访问口，把对外访问作为独立模块；访问目标的地址族由该模块处理，默认优先 IPv4。

本记录取代此前代理将“完全分开”扩展为两套业务栈及所有 DNS、连接池和资源预算均按接入地址族拆分的解释。该解释已从 AGENTS 删除，未据此实现新业务栈。

## 已确认的原则

- IPv4、IPv6 接入节点有独立节点身份、接入配置和认证凭据。
- 各协议完成接入鉴权与解码，统一提交目标访问请求；对外访问模块独立于具体接入协议。
- 目标网站与节点接入地址族独立。原记录提出网站IPv4优先；最新范围按0010限定为本节点负责的双栈目标路径，远端分流保留原目标并执行远端策略。
- 保持节点身份和资源归属可追踪；共享访问服务不能造成跨节点鉴权、配额或会话混用。

本记录形成时将“统一访问口”限定为内部服务接口。2026-11-01用户进一步明确，所有节点必须共享同一个出站调度器，出站作为独立模块全局共享；以[0009](0009-global-egress-dispatcher.md)为准，不能仅共享接口或代码。是否另外提供同端口协议分流、固定出口IP或绑定接口，不由该原则自动确定。

## 实现建议与影响

新增独立 `egress` 职责，在 core-api 定义窄的目标访问契约，由 engine 负责节点、会话、取消和装配，egress 协调 routing、dns、net 与具体出站实现。协议不各自复制目标网站的解析与地址选择规则。

IPv4 优先的候选安排建议为：IP 字面量按其地址族连接；域名有 IPv4 候选时先尝试 IPv4，在允许的建立预算内再尝试 IPv6。已发送业务数据的会话不跨候选重放；UDP 建立后固定当前流的目标。精确预算和解析执行方式随接口实现确定。

本记录形成时主要是客户端出站和固定目标转发入口，当时尚缺完整节点鉴权和目标服务。当前快照已不同，实际范围以根STATUS及接口为准；旧任务安排不作为恢复开发授权。

## 验证目标

在 worker 验证两类节点各自鉴权、凭据互用被拒绝、不同协议进入同一目标访问服务、跨族目标访问、IPv4 优先与受限 IPv6 回退，以及节点归属下的会话、配额和资源退出。此处只记录目标，没有新增通过结论。

详细设计见[节点与统一目标访问](../node-egress.md)。
