# 协议开发阶段与工作流

状态：流程由用户明确，具体发行范围、角色和任务顺序仍待决定。日期：2026-10-30。

**协议范围、各核心支持情况、组合限制和建议任务统一维护在[三核心协议与组合总表](../reference/reports/三核心%20协议%20组合支持.md)。**本文只保存阶段、框架范围和开发流程，不另列一份协议名单。当前总表是静态源码调研，不是 kerlico 已实现能力。

## 当前流程

用户最新要求先集中查明三个参考核心的协议与组合，形成可持续使用的总表；此前不提前开展这类调研的限制由[0002 决策](decisions/0002-support-catalog-before-implementation.md)取代。实现顺序保持框架先行，再一次研究、实现和验证一个角色及最小组合。

集中调研覆盖类型、方向、传输、安全/flow、数据能力及主要限制。每个实际开发任务开始前，仍需复核所选基线、规范、依赖、许可证和对端，并解决总表标出的未知项。资料完成、认可清单或确定顺序不自动授权开始编码。

## 阶段安排

| 阶段 | 交付边界 | 总表入口 |
| --- | --- | --- |
| 支持目录 | 保存固定上游能力和限制，确定当前项目候选；不实现或宣称互通 | P/E/A/D 目录与 V 组合观察 |
| F0 框架 | 完成最小装配、流包契约、调度、取消与退出的独立验收 | K-F0 |
| 本地接入 | 每次接入一个有明确角色、数据能力和验收条件的入口 | K-L 系列 |
| 远端最小路径 | 每次选择一个出站及其安全/传输组合，形成端到端验证 | K-S/K-T/K-V 系列 |
| 其他协议与接入 | 按实际需求选择任务；系统接入不必等全部协议完成 | K-R/K-A/K-E/K-B 系列 |

以上任务阶段不确定首批 OS 或客户端/服务端优先级，也不将上游联合目录全部列为发行承诺。具体范围和优先级在总表的任务条目中记录。

## F0 框架的最小范围

框架以[核心契约](core-contracts.md)为起点，只落实首条路径所需部分，不一次建立整棵目标目录。

1. 一个程序入口与最小 workspace，启动、退出和配置检查入口清晰。
2. 地址、标识、会话上下文、流/数据报、错误与建立预算的初版契约。
3. 模块描述、显式注册、外层配置、私有构造计划和能力/引用校验。
4. 最小调度、连接器及基础动作；测试替身用于验收装配，不作为发布协议。
5. 任务归属、取消、有限队列、部分失败清理与有截止时间的关闭。
6. 只读能力/状态视图和对应行为验证，不要求先交付完整控制 API、规则语言或在线替换。

没有真实代理入站时，业务运行明确报告缺少能力；配置检查和模块列表可以工作，不能展示不存在的协议。框架独立验收，不为候选协议预建空实现或无效 feature。

| 框架验收场景 | 目标行为 |
| --- | --- |
| 未知模块、缺少角色或引用错误 | 运行前明确报错，不静默改为直连 |
| 多个测试模块装配 | 依赖与实例隔离，核心不根据具体协议名分支 |
| 构造/启动中途失败 | 已取得资源有清理结果，未就绪入口不接业务 |
| 流/包交接和预读 | 保留关闭语义、边界、地址与所有权，不丢不重 |
| 排队、取消与停止 | 容量与预算有界，没有脱离所有者的后台任务 |
| 首个和第二个协议接入 | 改动集中于模块及装配；必要接口变化有理由和回归验证 |

这些仍是未来验收目标，本轮没有 Cargo 工程、测试替身或代码。

## 每个组合任务的开发循环

先引用总表中的稳定 ID，限定角色、版本、传输、安全/flow、数据能力和最低验收。随后复核对应规范与源码，查明必要依赖和未知项，形成局部设计，再实现、互通和异常验证。完成既定范围、更新状态后进入下一项；不以完成一个组合代表同协议全部组合可用。

| 开工前主题 | 必须补齐的当前任务信息 |
| --- | --- |
| 协议与对端 | 固定版本、规范、角色、数据语义、参考对端与最低交付 |
| 传输/安全/flow | 实际路径、合法和拒绝组合、默认行为、别名、构建与运行条件 |
| 依赖与模块边界 | 库、许可证、复用部分、协议特有逻辑及接口调整 |
| 验证 | 流/包、认证失败、异常报文、超时、取消、关闭、回写与资源回收 |
| 构建/性能 | 工具链、目标和资源条件；无测量时不填写性能结果 |

详细支持状态和组合编号只更新总表；实际实现说明归模块，汇总进度归 [STATUS.md](../STATUS.md)。编译测试资源见[编译与测试安排](build-and-test.md)，真实连接资料只在本地私有目录。
